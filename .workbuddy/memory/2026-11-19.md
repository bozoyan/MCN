## 0.5.8 macOS Debug / Release 构建

- 版本号两处同步为 `0.5.8`：`pubspec.yaml` 与 `lib/shared/app_config.dart`（与 `release.sh` 同步逻辑一致，未执行 release.sh 的 commit/tag）。
- 构建前置一律需要注入 rust PATH：`$HOME/.cargo/bin:$HOME/.rustup/toolchains/1.97.1-aarch64-apple-darwin/bin`，否则 native asset 构建报 `could not execute process rustc -vV`。
- **SwiftPM 嵌套沙箱坑（新增）**：在受限沙箱内跑 `flutter build macos` 会报 `xcodebuild: error: Could not resolve package dependencies: sandbox-exec: sandbox_apply: Operation not permitted`。根因是 macOS 不允许嵌套 Seatbelt，xcodebuild 的 SPM 清单求值会再起一层。解法是给 xcodebuild 传 `-IDEPackageSupportDisableManifestSandbox=1 -IDEPackageSupportDisablePluginExecutionSandbox=1`；Flutter 经 `/usr/bin/arch -arm64e xcrun xcodebuild` 调用，所以在 PATH 前置一个 xcrun 包装脚本注入这两个参数即可（`/tmp/xcrunwrap/xcrun`）。同时包装里 `unset XROS_/TVOS_/WATCHOS_/IPHONEOS_/DRIVERKIT_DEPLOYMENT_TARGET`，解决 Xcode 27.2 的 Debug `clang: conflicting deployment targets`。
- 构建使用 `--no-pub`，避免 pub get 卡在 Resolving dependencies。
- 产物：`build/macos/Build/Products/Release/Reveric.app`（151MB，`ai.reveric`）、`Debug/Reveric.app`（366MB，`ai.reveric.debug`）；Debug 备份 `build/dist/Reveric-0.5.8-debug.app`。两者均 adhoc 签名。
- 注意：本次构建期间出现提交 `a26b9b1`（1.1119.2243），把 `flutter pub get` 改写的 `pubspec.lock`（镜像从 pub.flutter-io.cn 切到 pub.dev，70 个包升级）一并提交，非本次构建操作所为。原始 lock 备份在 `/tmp/pubspec.lock.0.5.7.bak`。

## 重新构建 0.5.8（23:30）
- 现象：项目里 `build` 消失。排查发现 `build` 曾是 git 跟踪的**软链**，指向外置卷 `/Volumes/BO/TEMP/MCN/build/reveric`（早期把构建产物外置的历史遗留），该软链在上一次提交里被删除，导致根目录 `Debug` 软链悬空。
- 中途出现的 `build -> /Volumes/BO/TEMP/MCN/build` 是 11-01 的旧构建树，其 `Release/FlutterMacOS.framework/Versions/A` 缺二进制，Release 链接直接报 `ld: framework 'FlutterMacOS' not found`（Debug 却正常）。
- 处理：`rm build` 移除软链（只删链接），改用项目内真实 `build/`，全新建。Debug 1m45s → 365M/`ai.reveric.debug`；Release 1m24s → 151M/`ai.reveric`，均为 0.5.8 adhoc 签名，`Debug` 软链恢复正常可解析。
- 结论：不要把 `build` 做成指向外置卷的软链；`/build/` 已在 .gitignore，改为真实目录后无需再跟踪。
