## 一、问题与根因

1. **对话出图后只显示「生成照片 已完成」,点开没有图片**:根因是 `importGenerated` 的 `finally` 会删除生成结果的临时文件,而弹窗把这条已失效的临时路径写进了图片块,卡片检查文件不存在就不渲染图片。图片本体已入库(资产 `ast_*`),用户在图库能找到但对话里看不到。修复:块里改存图库资产的持久相对路径(`file_workspaces/<作品>/images/gen_*.png`)。
2. **拍照弹窗尺寸下拉出现「5:4 · 2K (null)」**:`if (expr case final size)` 的 `final` 模式会匹配 null,过滤无效。MOSS 尺寸表 2K 档本就没有 5:4/4:5,缺项的 null 进了下拉。修复:两处改为可空模式 `case final size?`。
3. **聊天顶部偶发 "BOTTOM OVERFLOWED BY 1.00 PIXELS"**:此前日志只有一行溢出文本无法定位。`FlutterError` 桥接补齐 `informationCollector` 的 widget creator 链,复现一次即可从日志定点。

## 二、新功能

### 2.1 快捷出图指令(不打开弹窗,参数用记住的默认值)

聊天输入框直接输入:

```
/出图 一只在窗边的橘猫 size=1440x816 lora=bozoyan/Q-FEIFEI:0.7
```

- `/出图` 与 `/img` 等价;`size=`、`lora=`(可多个,`repo` 或 `repo:权重`)可选,缺省段自动用参数记忆里上次使用的模型/尺寸/LoRA;
- 发送后直接生成,不进 AI 对话轮;结果以图片卡插入当前会话;
- **参考图附件**:出图按钮旁新增参考图按钮(最多 4 张),选中后以芯片显示、可逐个移除,生成时作为参考图下发(走图像编辑接口,参考图 + size/LoRA 同时生效)。
- 出图弹窗与指令共用同一生成入口(`submitChatImageGeneration`),行为一致。

### 2.2 AI 自然语言出图(工具通路扩展)

Run 工具 `character/item generate-photo` 的 options 扩展 `size`、`loras`、`asset_ids`(≤4 张参考图素材):AI 在对话里即可按用户指定的尺寸/LoRA/参考图出图,缺省沿用模型默认。多图编辑回调(`imageMultiEditCallback`)接入工具管理器并按作品入库,返回契约(带 asset_id)不变。帮助文本已更新说明新参数。

### 2.3 全屏图片预览

- 新共享组件 `showRevericImagePreview`:InteractiveViewer 缩放平移 + 关闭按钮;
- 对话出图卡片:点击图片即全屏预览(复用头像/照片的全屏体验);
- 画布:图片「查看」按钮改为全屏预览(此前是限制 60% 屏高的小窗);**双击画布图片卡片也可全屏**(视频/音频仍走原媒体弹窗);
- 头像/照片弹窗的全屏预览改为复用同一组件,三处行为一致。

### 2.4 生成中计时

画布节点的任务浮签在 `running` 状态时显示滚动秒数(如「生成中 · 37s」),以任务提交时间为基准每秒刷新,任务结束自动消失。

## 四、构建环境坑(本次遇到)

- **Xcode ModuleCache 与其他项目冲突**:`_Builtin_stddef is defined in both /Volumes/BO/TEMP/MCN/build/... 与本项目 build/...`——两个项目的模块缓存指向同一 hash 目录且互相污染,随后又出现 `framework 'FlutterMacOS' not found` / `Xcode build system has crashed`。修法:删除本项目 `build/macos` 后全量重建;若复发,连 `~/Library/Developer/Xcode/DerivedData` 一并清理,并避免让两个项目的构建共享同一临时目录。
