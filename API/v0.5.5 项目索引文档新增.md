## 一、背景

仓库原有 `AGENTS.md`(约 20KB)承载全部硬性开发约束与 Rule 路由,但缺少 Qwen Code 侧的入口索引:新会话要定位入口、分层、命令和数据归属,需要重新遍历 `lib/`、`Makefile`、`pubspec.yaml`。

本次新增 `QWEN.md`,定位为**精简索引**,只描述项目事实与代码位置,不复制 `AGENTS.md` 的规则条文——避免同一批约束在上下文里出现两份,后续维护时产生分歧。

## 二、文档内容

### 2.1 定位与边界

- 只回答「这是什么、代码在哪、命令怎么跑」。
- 硬约束(安全边界、数据删除、DB 迁移、i18n、表单、桌面页头、技能版本)仍以 `AGENTS.md` 为唯一真源。
- 动代码前先读 `AGENTS.md`,再按其中的路由读 `.agents/rules/*.md`。

### 2.4 核对后修正的细节

- `third/` 实际为 **9 个**本地 fork 依赖(初稿写 8 个)。
- MobX 仅存在于 `lib/third/flow`(第三方节点画布)内部,业务层未使用,初稿的「局部遗留」表述不准确。
- 平台范围以 `AGENTS.md` 为准:Windows/macOS/Android;iOS、Linux 有工程目录但不在支持范围。
- 双库 `schemaVersion` 只写「各自维护」,不写具体数字,避免随迁移过时。
- 版本号、Dart/Flutter 下限不写死,统一指向 `pubspec.yaml` 与 `.fvmrc`。

## 四、后续维护

- 新增目录或模块、调整构建命令、平台范围变化时,同步更新 `QWEN.md` 对应章节。
- 版本说明继续归档到 `API/`,命名 `v<版本号> <主题>.md`,不写进 `docs/`。
- `QWEN.md` 只做索引;新增或修改硬约束仍写进 `AGENTS.md` 与 `.agents/rules/`,不要在 `QWEN.md` 里另立一套规则。
