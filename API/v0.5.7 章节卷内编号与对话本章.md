## 一、问题

章节列表按卷内序号显示:第 2 卷的新章节显示为「第1章」;但 AI 对话里只拿到全书连续序号,同一章被称作「第7章 chp_xxx」。作者在对话里无法把 AI 说的章号与左侧列表对应起来。

根因:数据库 `chapters` 视图同时算了 `chapter_num`(全书连续)、`volume_num`(卷序号)、`volume_chapter_num`(卷内序号)。章节树用 `volumeChapterNum ?? chapterNum` 显示,而 `tools_read._readChapter` 只输出 `chapter_num` 与 `volume_id`,卷序号、卷内序号、卷标题都没进 AI 上下文。

## 二、AI 侧:补齐卷内编号

`Read` 工具的 chapters 资源新增三个只读字段,listing 与单章详情、字段路径读取都返回:

| 字段 | 含义 |
| --- | --- |
| `volume_num` | 所属卷的全书序号,根级章节为空 |
| `volume_chapter_num` | 卷内章节序号,与列表显示的「第N章」一致 |
| `display_label` | 列表完整标签,如 `第2卷·第1章·地下实验室`;根级章节为 `第7章·标题` |

- `chapter_num` 语义不变,仍是全书连续序号,`?chapter_num=N` 查询与排序行为保持原样。
- `display_label` 与桌面章节树共用同一套规则:卷内用卷序号 + 卷内序号,根级用全书序号,番外只用标题。
- 根级章节的卷信息为 `null`,避免伪造「第0卷」。

## 三、桌面端:章节右键「对话本章」

在章节右键菜单的「发布」上方新增「对话本章」,已发布章节同样可用。点击后:

1. 生成 `章节·第2卷·第1章·地下实验室·内容 chp_xxx` 并写入剪贴板;
2. 展开 AI 面板,把同一段文本追加到当前对话输入框,聚焦但不发送。

实现复用 `AiChatShortcutDraft`:文本追加到现有输入框、不新建会话、不切换当前会话,作者可以补完指令后自行发送。卷序号从侧栏已加载的章节节点里取,不额外查库。

新增 i18n key:`chapter.chat_about`(对话本章 / Chat about this chapter)。

## 五、构建产物

版本号 `0.5.7`,macOS 两份产物:

| 类型 | 路径 | Bundle ID |
| --- | --- | --- |
| Release | `build/macos/Build/Products/Release/Reveric.app`(156.4MB) | `ai.reveric` |
| Debug | `build/macos/Build/Products/Debug/Reveric.app` | `ai.reveric.debug` |
| Debug 备份 | `build/dist/Reveric-0.5.7-debug.app` | `ai.reveric.debug` |

Debug 构建在本机曾失败,报 `clang: error: conflicting deployment targets, both '27.2' and '27.2'`。根因是 Xcode 27.2 在 macOS 构建中同时导出 `XROS_DEPLOYMENT_TARGET`、`TVOS_DEPLOYMENT_TARGET`、`WATCHOS_DEPLOYMENT_TARGET`、`IPHONEOS_DEPLOYMENT_TARGET`(均为 27.2),clang 把目标解析成 `arm64-apple-xros27.2.0`。Release 不走 `debug_app.cc` 的编译路径,所以未触发。

绕过方式:构建时用包装 `xcrun` 清掉这些非 macOS 变量,不改项目文件:

```bash
mkdir -p /tmp/xcrunwrap
cat > /tmp/xcrunwrap/xcrun <<'EOF'
#!/bin/bash
unset XROS_DEPLOYMENT_TARGET TVOS_DEPLOYMENT_TARGET WATCHOS_DEPLOYMENT_TARGET
unset IPHONEOS_DEPLOYMENT_TARGET DRIVERKIT_DEPLOYMENT_TARGET
exec /usr/bin/xcrun "$@"
EOF
chmod +x /tmp/xcrunwrap/xcrun
export PATH="/tmp/xcrunwrap:$PATH"
make build-macos
```

`pubspec.lock` 在构建时会被 `flutter pub get` 从 `pub.flutter-io.cn` 改写成 `pub.dev` 并升级 dev 依赖,构建后需 `git checkout -- pubspec.lock` 还原,不要随功能改动一起提交。

## 六、取消应用内自动更新

本次同时关闭应用内自动更新,应用版本以 `pubspec.yaml` 与本机构建产物为准。

- 新增编译期开关 `appUpdateEnabled`(`lib/shared/app_config.dart`),默认 `false`;需要恢复时用 `--dart-define=REVERIC_APP_UPDATE=true` 构建。
- `LatestRelease.build()` 在关闭时直接返回 `UpdateUpToDate`,不发起任何网络请求;`refresh()` 变为空操作。
- `UpdateService.checkForUpdate()` 与 `downloadUpdate()` 增加同样的短路保护,即使被直接调用也不会检查或下载。
- 关于页隐藏「更新」区块,只保留版本号;桌面侧栏与移动端设置入口依赖 `availableUpdate` 为空自动隐藏。
- `appVersion` 从硬编码的 `0.5.0` 同步为 `0.5.7`,与 `pubspec.yaml` 一致。
- 测试同步调整:provider 测试改为断言「关闭后不请求」;关于页与提醒测试删除已不存在的检查、下载、重启交互用例,保留署名与调试预览用例。
