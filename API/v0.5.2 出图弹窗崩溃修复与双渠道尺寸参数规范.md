# v0.5.2 出图弹窗崩溃修复与双渠道尺寸/参数规范

更新日期:2026-11-01

## 一、问题与根因(应用日志铁证定位)

1. **出图弹窗「无法选择模型与 loras 参数、点生成无反应」**:日志 `Bad state: Type mismatch between hooks: previous _StateHook<List<ModelScopeLora>> → new _TextEditingControllerHook`(`image_request_extras_panel.dart`)。参数面板的魔搭/MOSS 两个 section 是同一个 HookWidget 内的分支方法,各自 hook 数量与类型不同;在弹窗中把模型从魔搭切到 MOSS(或反向)时同一 element 位置的 hook 类型变化,弹窗构建崩溃、界面卡死。
2. **点生成后无响应/生成被打断**:日志 `A ValueNotifier<bool> was used after being disposed`(`image_dialog.dart:276`)。点击生成 → 弹窗 pop 销毁 → `generate()` 继续执行,对已 dispose 的 `generating` hook 状态赋值抛异常,中断已排程的生成流程。
3. **封面工作台 MOSS 出图报「尺寸不受支持」**:封面 3:4 + 2K 档算出 1536x2048(总像素 314 万)超 MOSS 上限 209 万,MOSS 客户端原样透传未收敛;次日重试改用合规档后成功,与日志一致。
4. **聊天窗口顶部偶发 "BOTTOM OVERFLOWED BY 1.00 PIXELS"**:FlutterError 桥接只落一行异常文本,缺少 `informationCollector` 里的 widget creator 链,无法定位溢出组件。

## 二、修复内容

### 2.1 参数面板 hook 崩溃修复(`image_request_extras_panel.dart`)

魔搭与 MOSS 两个 section 拆成独立 HookWidget(`_ModelScopeExtrasSection` / `_MossExtrasSection`),面板本体改为无 hook 的 StatelessWidget。widget 类型不同使 Flutter 在协议切换时重建 element、hooks 从零持有,根除类型不匹配崩溃;开关默认值同步官方默认(增强开、水印关)。

### 2.2 弹窗销毁后状态赋值修复(`image_dialog.dart`)

移除 `generating` hook 状态:点击生成后弹窗立即 pop,生成由会话流承接,不再触碰已 dispose 的弹窗状态;生成按钮可用条件去掉多余的 generating 判断。

### 2.3 MOSS 按官方文档显式默认参数(`moss.dart`)

按用户提供的 `Moss_API文生图.md` 调整请求体:

- `output_watermark`:默认显式发送 `{"enabled": false}`(**默认关闭可见水印**),面板开关显示同步为默认关;
- `prompt_enhance`:默认显式发送 `true`(文档默认),面板开关显示由「关」修正为「开」,消除 UI 与实际行为不符;
- `negative_prompt`:仍仅非空时发送;
- `n: 1`、`response_format: 'url'` 保持。

新增 `clampMossSize`:尺寸不满足官方约束(每边 256-2048、16 的倍数、总像素 ≤2097152)时等比收敛并向 16 对齐,过小则放大到下限——封面 2K 档等按通用档位算出的尺寸不再被服务端拒绝。测试覆盖:合规原样返回、1536x2048 / 2048x2048 收敛、非 16 倍数对齐、非法格式透传。

### 2.4 魔搭尺寸表改三档(`channels.dart`)

按用户指定的档位语义(1K 最大边 1024 / 1.5K 最大边 1440 / 2K 最大边 2048)重排魔搭通用表为 **13 比例 × 1K/1.5K/2K 三档**:等比推算取 16 的倍数,短边不足平台下限 512 时抬到 512 重算长边(1K 档 21:9 = 1200x512)。全部尺寸满足每边 512-2048、16 的倍数、总像素 ≤4,194,304。画布/聊天/拍照/封面各入口的尺寸下拉自动多出 1.5K 档。

### 2.5 溢出诊断增强(`flutter_error_logger.dart`)

FlutterError 桥接把 `informationCollector` 的定位信息(widget creator 链)拼进日志;此前 RenderFlex 溢出只落一行异常文本,无法定位组件。再次复现时日志将直接给出溢出 widget 的构建链。

`pubspec.yaml` 0.5.1 → 0.5.2。
