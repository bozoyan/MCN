## 一、需求

两项出图能力补齐：

1. **ModelScope LoRA 触发词前置**：LoRA 模型需要把清单里的触发词放到总提示词最前面，否则出图不生效。清单为外置 `modelscope_models.json`，换清单不改代码。
2. **新增 BizyAir 供应商**：走 modelzoo openapi（12 个端点）与 webapp openapi（FEI 两个应用，后期继续增加），按用户决定拆成两个独立供应商类型，而不是一个供应商挂两种模式。

## 二、ModelScope LoRA 清单与触发词

新增 `ModelScopeLoraCatalog`，运行时解析外置 JSON，不打包进 asset。

- **解析**：遍历顶层所有数组（`LORA` / `EDIT` / `FEI` 等），每条取 `Model`（LoRA 仓库 ID）、`Bmodel`（底座）、`prompt`（触发词）、`Name`、`Purl`，按 `Model` 去重；空触发词不进反查表。
- **反查**：`triggerFor(repoId)` 以 `Model` 字段为键，与 LoRA 行自身携带的字段无关。
- **拼接**：`prefixTriggers(userPrompt, loras)` 按 LoRA 顺序逐个反查、去重，结果形如 `触发词1, 触发词2, 用户提示词`；无命中时原样返回。
- **降级**：文件缺失、JSON 损坏、字段类型不符都退化为空清单，不阻塞出图。
- **查找顺序**：启动工作目录 → 应用数据目录 → 可执行文件同目录。空结果不写进程内缓存，补齐文件后下一次仍有机会读到。

已接入 `ModelScopeImageClient.generate()`：构造请求体前，若带 LoRA 则前置拼接后再写入 `prompt`。

## 三、BizyAir 拆分为两个供应商

| 供应商类型 | 图片协议 | 渠道数量 | 用途 |
| --- | --- | --- | --- |
| `AiProviderType.bizyair_modelzoo` | `ImageProtocol.bizyair_modelzoo_image` | 12 | Nano Banana 2.1 / 2 / Pro、GPT-Image-2、GPT-Image-2.5 Sunburst / Flare，各含文生图与图生图 |
| `AiProviderType.bizyair_webapp` | `ImageProtocol.bizyair_webapp_image` | 2 | FEI 应用 `57932`、`57807` |

- 两者固定 BaseURL `https://api.bizyair.ai`，各自独立配置 Key 与模型列表，互不影响。
- webapp 后期加应用只需在渠道表新增一条 `web_app_id` 记录，无需改客户端。
- 目录条目复用既有 catalog（`gemini-nano-banana-2.1`、`gpt-image-2`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`），渠道层用独立 capabilities 覆盖比例集合与参考图上限：文生图端点 `maxReferences: 0`，图生图端点允许最多 10 张。

### 提交与轮询

- **modelzoo**：`POST /v1/modelzoo/tasks/openapi/<通道>`，body 为 `prompt` / `aspect_ratio` / `resolution`（`1k`/`2k`/`4k` 小写）；有参考图时补 `image_urls`。返回 `data.request_id`。
- **webapp**：`POST /v1/webapp/task/openapi/create`，头带 `X-Bizyair-Task-Async: enable`，body 为 `web_app_id` 与 `input_values`（宽高按 16 的倍数取整、最大边不超过 2048）。返回 `request_id`。
- **轮询**：拿到任务 ID 后先等 60 秒，之后每 5 秒查询。modelzoo 查 `/v1/modelzoo/tasks/openapi/<id>`，`data.status=Success` 后取 `data.outputs.images[0]`；webapp 先查状态，成功后再查 `/outputs` 取 `data.outputs[].object_url`。
- **参考图**：BizyAir 不识别 base64。外链 URL 直接交给服务端拉取；本地路径与 data URI 先经转存接口 `https://b.slas.cc/api/bizyair/upload` 换成公网 URL，失败时给出明确错误。
- 错误分类复用 `classifyAiImageError`，日志走 `writeImageLog`。

## 四、多密钥池与串行任务队列

BizyAir 一个 Key 对应一个并发任务，多 Key 才能并行分摊额度。新增 `BizyAirKeyPool`：

- **Key 字段三种写法**：直接填密钥池 txt 路径；填多把 Key（每行一把，逗号或空格分隔）；留空则尝试 `~/PY/2026/bizyair/bizyair_BOZO.txt`、`~/.bizyair/keys.txt` 与 `BIZYAIR_API_KEYS`。
- **解析规则**：`#` 开头为注释，兼容 `KEY=value` 与 `export KEY=...`，去引号与空白。
- **游标持久化**：`${supportRoot}/bizyair_key_cursors.json`，按供应商 id 分槽；任务成功后才 +1 轮转，失败重试不消耗轮转位。
- **失败切换**：提交失败时串行换下一把 Key 重试，全部失败才抛错；提交成功后固定在可用 Key 上，后续轮询沿用同一把（任务归属）。
- **串行队列**：按供应商 id 维护任务队列，一把 Key 同一时刻只跑一个任务；前一个任务失败不阻塞后续任务。

## 九、构建环境注意事项

本次构建遇到两类环境问题，处理方式已写入 `AGENTS.md` 的「macOS 本地构建」:

1. **Rust 工具链 PATH**:未注入 `~/.cargo/bin` 与工具链 bin 时，native assets 构建报 `could not execute process 'rustc -vV'`。
2. **SwiftPM 嵌套沙箱**:受限会话中 xcodebuild 解析 SwiftPM 依赖报 `sandbox-exec: sandbox_apply: Operation not permitted`。用 PATH 前置的 `xcrun` 包装脚本注入 `-IDEPackageSupportDisableManifestSandbox=1` 与 `-IDEPackageSupportDisablePluginExecutionSandbox=1`，同时 `unset` 非 macOS 的 deployment target 变量，一并解决 Xcode 27.2 的 Debug `conflicting deployment targets`。

另注意 `flutter pub get` 会把 `pubspec.lock` 改写为 `pub.dev` 源并升级可兼容版本，不宜随功能改动提交。
