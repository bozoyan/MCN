# 关系图与伏笔兑现

用于展示人物、势力及其他资源之间的关系，或追踪伏笔的铺垫与回收。画布连线只表达这张图的关系；仅要求画图时，不据此修改作品的实体关系记录。

## 人物与势力关系

- 按用户关注的人物、阵营或冲突读取相关资源，使用引用节点；不为了画图复制一套人物或势力。缺少资源但仍处于构想阶段时，可用便签标明候选设定。
- `relationship` 表示人物、势力等关系，通常需要简短标签，如“同盟”“师徒”“敌对”。它没有箭头；上下级等需要区分两端角色时，用“甲领导乙”这样的标签或说明表达，不把存储端点顺序当作可见方向。
- 资料关联使用 `association`；只有确实在分析“某事件导致关系变化”时才使用 `causal`，不把关系图改造成时间线。
- 原文证据、设定和猜测应区分。未知关系不靠模型补齐；不要为了图密而把所有人物两两相连。

纯关系图不使用要求有向边的树形排列。可按阵营手动分组；以一个中心人物为重点时可采用 `auto` 的两行布局：

```text
row=0   [配角1] [配角2] [配角3] [配角4]
row=1             [主角]
```

主角用 `relationship` 连向相关配角；`auto` 会把单节点放到邻居的列均值上。节点较多的配角行承担骨架，不因主角重要就把单节点行当作骨架。骨架行与网格规则遵循入口的「通用摆位与连线规则」。不需要关系线的资源清单可用 `grid`。

## 伏笔与兑现

- 引用已有伏笔与章节，区分“已经铺垫／兑现”和“计划铺垫／兑现”；梳理任务不擅自创造回收情节。
- `foreshadow_payoff` 的有效端点是伏笔引用 → 章节引用。剧本场次不能作为这种边的终点；需要展示场次中的铺垫或回收时，用场次引用与 `association`，在标签或便签中明确说明，不冒充专用兑现边。
- 用 `timeline` 连接需要展示顺序的章节；未回收的伏笔可以保留为未连接的引用，配便签说明，不能为了消除孤点虚构兑现。
- 按章节对齐时，将章节主干放在节点最多的一行，伏笔放相邻行后执行 `auto`；按有向兑现关系展开时可选 `tree_lr`。先选阅读方式，再排列。

### 伏笔兑现表模板

```text
row=-1   [伏笔A]   [伏笔B]   [伏笔C]
row= 0   [第3章] → [第7章] → [第11章] → [第15章]
```

章节使用引用节点，按 `timeline` 连接；每条 `foreshadow_payoff` 从伏笔引用指向它兑现的章节引用。只有一个兑现章节的伏笔在 `auto` 重排后会对齐该章节；不需要逐节点计算横坐标。未兑现伏笔保留未兑现状态，不补造目标章节。

## 检查

关系标签是否能区分合作、冲突和普通关联？两端角色是否明确？伏笔是否连接正确的兑现资源，计划是否被误写成事实？本场景不要求剧情树的入口、选项或结局。
