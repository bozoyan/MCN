# 分支剧情

用于选择路线、多结局、分支汇合与循环；工具字段与通用操作见入口指南。

## 任务与范围

- **梳理已有剧情**：读取用户指定的章节、场次或大纲，提取已有事件与关系。线性故事可以画成推进链，不为凑成树擅自增加选择、结局或改写原文；不确定的关系标为待核实。
- **创作分支剧情**：沿用用户给出的起点、人物目标、关键冲突和结局约束，设计选择及后果。只有“剧情树”不足以判断是否允许改写已有故事时，先澄清这一点；已经明确的要求直接执行。
- **修改已有树**：保留未涉及的节点、资源引用和连线，围绕指定分支增改。只要求画图时，不顺带创建或重写场次正文。

## 构建路线

1. **保持合适粒度。** 一个节点表达一个场次、关键事件、选择或结果。已有场次使用 `reference` + `screenplay_scene`，已有章节使用 `reference` + `chapter`；未落地的构想使用 `sticky`。这些叙事角色写在标题和正文中，不新增节点类型或字段。
2. **让选择有后果。** 分叉说明角色能做什么，以及各选项带来的行动、信息、关系或代价变化。用 `timeline` 表示剧情进入下一段，用 `causal` 表示事件导致后果；不把同时发生的支线误写成互斥选择。
3. **明确分支标签。** 选择节点的每条出边写清选项或进入条件，例如“交出证据”“隐瞒证据”。长条件和后果放到对应便签正文。标签只是作者说明，不会执行条件、修改变量或驱动游戏。
4. **保留不同选择的身份。** 同一对端点、同一种类型不能重复连边。两个选项最终到达同一场次时，分别建立选择或后果便签，再连到共同场次，不合并选项标签，也不靠更换边类型绕过限制。
5. **核对汇合前提。** 汇合前检查各路线的人物去向、持有物、已知信息和关系状态。若后续场次依赖某条路线独有的信息，就补上获准创作的过渡或继续分开；不能为了图形整齐抹掉分支后果。共同场次复用同一个节点。
6. **标明入口与终点。** 在节点标题、便签或画布说明中标明入口、结局与待续处；不要把没有入边或出边自动解释成故事起点或结局。循环可以保留，但应说明返回原因和退出方式。

剧情主干的事件便签统一使用 `sand`，决策点可用 `rose` 强调；背景与备注遵循入口的纸色含义，不为每一条分支新增一种颜色。

## 决策点与选项的命名

决策点表达“要决定什么”，分支标签表达“可以怎么选”，后果节点表达“选完发生什么”。不要把先后发生的决策点命名为“选A”“选B”或“选1”“选2”，这容易让人误以为它们是同一次决策的互斥选项。

| 位置 | 命名示例 |
|---|---|
| 决策点 | 选择囤货路线、决定改造优先级、是否告知母亲真相 |
| 选项标签／选项便签 | 去五金店、去超市、优先焊门、告知真相 |
| 后果节点 | 获得门锁材料、与继妹提前交锋、母亲加入准备 |

例如两次连续决策应写成“选择囤货路线 → 各路线事件 → 决定改造优先级”，不要写成“选A → 各路线事件 → 选B”。确需编号时作为辅助标识，仍保留有意义的名称；用户指定的编号不擅自删除。引用节点保留原资源标题，需要补充决策问题时用相邻便签，不为规范画布命名改写原资源。

例如“发现证据后选择公开或隐瞒，最后在车站对质”：

```text
             ┌─公开证据→ [遭到追捕] ─┐
[发现证据] ──┤                      ├→ [车站对质]
             └─隐瞒证据→ [秘密约见] ─┘
```

四条推进边使用 `timeline`，两个分支正文分别记录后果。汇合前确认“车站对质”在两条路线下都成立；若对质内容依赖是否公开证据，就保留路线差异，不能直接共用同一段正文。节点和连线写入完成后，调用一次 `tree_tb`。

## 布局与检查

先创建完整节点和有向连线，再执行一次 `tree_tb`：分支剧情与影游一律从上到下展开，选项在决策点下方并排、汇合点居中，用户没有明确要求横向时不用 `tree_lr`。已有分支图增删节点后写 `tidy`，沿用原布局。不套用 `auto` 的主干分行规则，不为排列整齐减少分支或把不同路线强行汇合。

- 沿剧情推进边，从指定入口能否到达每条路线？没有出边的节点是结局、待续处，还是漏连？背景资料和备注不要求接入剧情路线。
- 决策点是否说明要决定什么，出边是否区分选项，后果是否可辨认？有没有用“选A／选B”混淆先后决策和互斥选项？
- 汇合后的场次是否与每条入路都兼容？不要把所有路线的独有事实无条件写进同一段后续正文。
- 循环是否有明确用途与退出说明？数值与条件目前只是作者说明，不能宣称已经实现可运行的影游逻辑。
