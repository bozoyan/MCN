# 灵感、资料与方案比较

用于收集尚未成形的想法、组织参考资料、比较多个创作方向。内容可以彼此独立，不要求形成剧情链。

## 收集与分组

- 已有素材、设定、人物或大纲使用引用；新灵感、问题、假设、方案摘要使用便签。标题说明内容，如“封闭空间悬疑”“主角动机待补”，不只写“想法1”。
- 按任务需要分组，例如主题、人物、场景、候选方案或待核实项。不要把一种固定分类强加给所有灵感板。
- 比较方案时，每张候选便签写清核心设想和决定取舍的差异；长篇方案引用原文。尚未选定的方案保留候选身份，不把互斥构想同时写成作品事实。
- 色彩可以辅助分组，组名和标题仍要独立可读。只整理画布时，不顺带修改资料的原有分类或正文。
- 按候选方案分组需要另定纸色含义时，在图中明确说明，并遵循入口的三色上限和同色同义原则，不强套剧情图的主干配色。

## 连线与布局

- 默认不连线。只有需要说明来源、启发或关联时使用 `association`，并在不明显的关系上写简短标签。
- 无方向的资料关联不使用 `timeline` 或 `causal`；当任务转为组织剧情或分析因果时，再读取对应场景附件。
- 同类条目的清单用 `grid`。用户已按空间分组时保留坐标，按组追加；整图网格排列会移动所有节点，不能一边依赖空间分组、一边反复执行全图 `grid`。
- 分组标题和待办可用独立便签，不为消除孤点给它们补线。无需建立入口、结局或选择标签。

## 检查

已有资源有没有被重复抄成便签？候选方案和已确定内容能否区分？用户要比较的差异是否可见？局部补充是否保留了既有分组与位置？
