# 剧情结构与因果分析

用于梳理主线、时间线、节拍和事件因果。交互选择、多结局等任务改读 `references/branching-story.md`；平行发生的支线不等于互斥选项。

## 选取内容与连线

- 先确定范围和粒度：全书看幕或关键转折，单集看场次，局部看事件节拍。不要在同一条推进链中混入无关资料。
- 梳理已有内容时读取对应正文或大纲；正文事实与未写出的规划分开标明。线性故事保留为链，不为凑成树添加选择或后果。
- 已有章节、场次、大纲优先使用资源引用；没有独立资源的节拍用便签，一张写清一个动作或变化。标题直接写事件，如“发现失踪名单”“决定追查”。
- `timeline` 表示选定的叙事顺序或故事时间顺序；涉及倒叙、插叙时，在画布说明中明确采用哪一种。`causal` 表示原因导致结果，不能仅因为前后发生就认定有因果关系。
- 需要保留的先后与因果必须显式连边，不能只靠节点位置表达。背景说明可以不连线，不用 `association` 代替推进边。

## 选择布局

一般推进链用 `tree_lr`，纵向因果展开用 `tree_tb`。有向连线决定层次，不需要手算树形坐标。

只有需要“主干一行、前情与后果分行”的版式时，才按下面规则创建网格布局并使用 `auto`：

### 节拍时间线

```text
row=-1   [前情]        [动因]
row= 0   [发现] → [追查] → [对质] → [转折]
row=+1              [后果]
```

- 主干沿 `row=0` 从左到右，列序对应本图选定的时间或叙事顺序，主干便签统一使用 `sand`。
- 支线分行不混行：前情、动因、伏笔与暗线放 `row=-1`，影响、后果和代价放 `row=+1`；同一行不叙两条线。
- 先摆完整主干，再挂上下两行，最后连边，执行一次 `auto`。骨架行选择、节点尺寸与网格规则遵循入口的「通用摆位与连线规则」。

主干便签的创建示例；将 `{name}` 换成画布名，后续节拍依次增加 `col`：

```text
Create {"path": "/canvas/{name}/nodes", "fields": {"type":"sticky","title":"发现名单","content":"主角发现失踪名单，决定追查。","color":"sand","col":0,"row":0}}
```

### 因果树

```text
       [起因]
       ↙    ↘
   [结果A] [结果B]
    ↙   ↘
[余波A1] [余波A2]
```

用 `causal` 分别连接起因与结果、结果与余波，父在上、子在下。完成连线后调用一次 `tree_tb`，不需要逐节点手算坐标；每一条边都应有明确的因果依据。

## 检查

确认主线完整、事件顺序有依据、因果没有被时间相邻替代；未证实的关系标明待核实。图太密时按用户关注范围分层组织，不以删掉关键事件换取整齐。局部修订只更新相关节点与连线。
