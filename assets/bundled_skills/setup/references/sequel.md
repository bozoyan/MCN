# 续作初始化流程

在当前作品上下文中的 `type` 为 sequel 时使用。续作承接的是前作已经完成或已明确阶段性收束后的故事；不要把它当作同人，也不要询问同人的“故事线之前/平行/之后”位置。

## 1. 建立前作承接边界

先读当前工作区中已有的前作资料、结局、时间线、人物、世界观和大纲。用 AskUser 分轮确认：

1. 承接哪部前作，采用哪个结局、版本或已完成范围。
2. 前作中必须保留的结局事实、人物状态、关系、世界规则和未解伏笔。
3. 续作与前作相隔多久，是否换主角、换舞台或换核心冲突。
4. 前作资料是否足以说明“故事结束时世界处于什么状态”；若不足，要求用户补充，不能自行编造前作结局。

将前作的承接边界、不可推翻事实和时间跨度写入工作区资料。只有后续写作必须严格遵守的稳定边界，才能经用户确认后写成 AgentRule。

## 2. 确认续作为什么必须存在

续作不能只重复前作成功模式。确认：

- 前作已经解决了什么，续作不再重复解决什么。
- 哪个后果、代价、遗留问题或新变化，使得新的主冲突成立。
- 新主角或旧主角现在的目标、资源和局限。
- 前作读者能获得的延续体验，以及续作新增的核心体验。

若无法说清“前作结局之后为什么仍有必须讲的故事”，先停在这里澄清，不要急于取名或展开世界观。

## 3. 形成承接大纲

在前作边界与新主冲突确认后，生成一份候选续作承接大纲，至少包括：

1. 开局时距前作结局的时间和世界状态。
2. 前作人物、势力和伏笔在续作中的继承、退场或转化。
3. 触发新主线的事件与主角的新目标。
4. 与前作主题形成呼应但不重复的中段升级。
5. 续作独立高潮及其对前作遗留问题的回答。

用 AskUser 确认、修改或重做候选大纲；确认前不得写入工作区。确认后，将承接边界写入时间线/世界观资料，将续作主线写入大纲资料。

## 4. 完成通用初始化

承接边界与新主冲突确认后，再确认题材、读者、故事承诺、书名、分类、标签、简介和通用写作约束。

## 5. 结束检查

结束前确认：

- 前作采用范围和不可推翻事实是否明确？
- 续作是否拥有独立主冲突，而非重复前作？
- 角色、世界和时间线的变化是否能与前作结局相容？
- 候选承接大纲是否已经用户确认并落盘？
