# 同人初始化流程

在当前作品上下文中的 `type` 为 fanfic 时使用。同人可以取用原作人物与设定，但原著事实必须**有据可查**，不得凭模型记忆臆造 Canon。

整体顺序：先框定同人在原著中的**取材区间** → 就该区间建立一份**有据可查的原著参考大纲** → 在其上做**原创改写**。

若发现这其实是「你自己前作完结后的承接」而非在原著时间线内取材，说明作品性质应为续作，请提示用户改用续作流程，不要在同人流程里当续作处理。

## 1. 建立原作边界与取材区间

先读工作区中已有的人物、世界观与大纲线索。若「故事背景」中已有用户提供或确认的原作资料，先只做全局定位，不要在取材区间确认前通读完整时间线或批量读取每章剧情：

1. 从 `Read {"path":"/lore"}` 返回的实际路径进入「故事背景」，不要自行拼接嵌套资源路径。
2. 先读「原作名 - 剧情梗概」，了解全局主线和结局，作为框定取材区间的依据。
3. 用户提供或已核实的剧情梗概、完整时间线和每章剧情可作为参考资料，不算模型记忆；须保留来源，不能仅凭文档标题认定内容可靠。资料缺失、为空、互相冲突或与用户指定版本不符时，必须说明缺口并 AskUser，不能自行补全 Canon。

完成上述读取后，再用 AskUser 分轮确认：

1. 基于哪部原作或前作、采用哪个版本与时间范围（取材区间）。
2. 哪些人物、设定、关系和重大事件必须遵守。
3. 允许偏离的范围：分歧点、切入点或偏离点、OOC 边界、是否改写原作结局。
4. 原著素材是否充分：剧情梗概是否足以支撑取材区间的初步判断；若不足，要求用户提供或确认可用的资料，**不能自行捏造 Canon**。模型仅凭训练记忆得到的部分，必须标为「待用户核实」，核实前不算 Canon。

取材区间确认后，再按区间核对原作状态，不要为了初始化机械读取整份文档：

1. 读取「原作名 - 完整时间线」中与取材区间相关的章节，核对事件顺序、因果关系及人物与世界状态。完整时间线较长时，用 Grep 定位章节标题或关键事件，再按返回的行号分页 Read。
2. 需要核对具体冲突、章末钩子时，再读「原作名 - 每章剧情」中对应章节；不要批量读取全部章节文档。
3. 需要查证原文时，可按 `原文证据` 定位取材区间内的对应章节，用 `Read /works/{work_id}/chapters?chapter_num=N` 找到章节，再读其 `content`；剧本原作按剧本工具指南读取对应场次正文。
4. 已有摘要与原文都需核对版本、取材区间和上下文；两者互相冲突或与用户指定版本不符时，列出来源与分歧并 AskUser，不默认任一方无条件优先。资料仍有缺口时说明缺口，不能自行补全 Canon。

将已确认采用的原作事实、采用范围和分歧点写入当前工作区资料（世界观、角色、大纲轨道），注明来源，区分参考设定与当前作品正文已发生的事实。本作关系与证据只能引用本作实体和章节 ID。只有「后续写作必须严格遵守」的边界，才能在用户确认后提炼为 AgentRule。

### 确认故事线位置（必选其一）

- **故事线之前**：原作开篇前发生的故事。
- **故事线平行**：与原作主线同期发生、会交汇或错位的独立故事。
- **故事线之后**：从原作或前作已知终点继续。

不要把三者混为同一个大纲。三种位置对「原著参考大纲」的用法不同：

- **平行**：与原著同期，需在原著大纲上逐拍改。
- **之前**：原著尚未开始，原著大纲退化为「原著开篇时的已知状态」，同人必须收敛到该状态。
- **之后**：从原著终点续写，原著大纲退化为「原著结局状态」，同人在其后展开。

## 2. 建立原著参考大纲（取材区间内）

目标不是还原原著全书或复述完整剧情，而是就取材区间建立一份原著大纲，作为原创改写的**基线**。

- **区间限定**：只覆盖同人主线会触及的原著范围，不整本铺开。
- **来源限定**：原著大纲只能总结自已提供或已核实的素材；模型记忆产出的内容先标「待核实」，用户确认前不作 Canon，更不能当改写基线。
- **不得机械照搬原著章节**：分卷/节拍服务于「哪里可改、哪里是硬 Canon」，不是复述剧情；不得直接复用原著正文或标志性表达。
- **用户主导分卷**：先用 AskUser 确认这份原著参考大纲切几段（卷/阶段）、每段覆盖的原著范围。AI 可依据篇幅或时间线建议切法，但不得擅自定卷，或假设原著分卷。

就每段整理时，下列是**可选维度，不是固定模板**：按当前同人的主角、题材和改编目标挑 2 到 5 项，可增删，不要为了填表强行补齐。

- **硬 Canon 锚点**：该段必须遵守的起止范围、重大事件、角色状态变化、死亡/失踪、信息揭示。
- **可改编空间**：区分不可改的硬设定与可自由发挥的留白，以及改动后会连锁影响的高风险节点。
- **关系线与伏笔接口**：可深挖的情感/权力/误解节点，可嫁接或反转的伏笔及其原作回收点。
- **名场面与情绪基调**：可呼应、错位或反转的场景与情绪机会；不得直接复用原作正文或标志性表达。
- **与同人主线的接口**：适合交汇、旁观、避开或制造分歧的节点。

把原著参考大纲落成**独立大纲轨道**，标题标明用途，例如「原著参考：第 X 卷」；需长期遵守的硬边界经用户确认后再提炼为 AgentRule。不得把未核实的 AI 推断混入 Canon。

## 3. 在原著大纲上做原创改写

按故事线位置进入对应分支。三种位置都要产出经用户确认的候选大纲与节拍表；确认前一律不得写入工作区。

### 故事线平行

在原著参考大纲之上生成**候选**同人大纲和节拍表：

1. 汇总各段的硬 Canon 锚点、可改编空间、伏笔与关系接口。
2. 确认同人主角的独立目标、资源限制、与原作主线的交汇窗口，以及哪些原作事件只能旁观、不可改变。
3. 逐拍在原著大纲上标注：分歧点从哪一拍开始、改变了谁的目标/关系、触发的蝴蝶效应波及哪些后续拍、哪些 Canon 结果仍须保留。
4. 节拍表每拍至少说明「发生什么、改变了谁的目标/关系、关联或刻意错开哪个 Canon 锚点、调用了哪个可改编空间或伏笔接口」。
5. 用 AskUser 展示大纲和节拍表，请用户确认、修改或重做。
6. 确认后：同人主线写入独立大纲轨道（如「同人主线：第 X 卷」），与「原著参考」轨道分开维护；交汇关系写入世界观或对应大纲轨道；需长期遵守的边界再单独写为 AgentRule。轨道的 `start_chapter_num` 与 beat 的 `chapter_count` 按 SKILL.md「大纲轨道」规则设置。

默认用以下八个节拍组织候选，题材不适用时可合并或替换：

1. 独立开局与主角目标。
2. 首个 Canon 阴影或旁证。
3. 平行线自己的触发事件。
4. 第一次与原作主线交汇、擦肩或冲突。
5. 独立目标受挫，必须作出选择。
6. Canon 大事件前后的介入、旁观或错位后果。
7. 平行线高潮：主角付出代价完成自己的选择。
8. 收束：与原作时间线重新对齐、分道或留下后续接口。

### 故事线之前

确认起点距原作开篇多远、已知事实的铺垫边界、故事最终接入原作的节点，以及接入后是否继续写。

核心约束：**前传结局必须收敛到原著开篇的已知状态**，不得与之冲突。在原著大纲的「开篇已知状态」之前，生成候选前传大纲与节拍表，末拍对齐原著开篇；AskUser 确认后，按平行分支同样的方式落盘（独立大纲轨道 + 必要边界提炼 AgentRule）。

### 故事线之后

确认承接的原作终点、角色现状、未解决后果和新主冲突；原作结局是否可改必须显式确认。

从原著大纲的「结局状态」之后，生成候选续写大纲与节拍表：首拍承接终点并给出新主冲突，中段与原著主题呼应而不重复，高潮回应原著遗留问题。AskUser 确认后按同样方式落盘。

## 4. 完成通用初始化

原作边界与故事线位置确认后，再确认题材、读者、故事承诺、书名、分类、标签、简介和通用写作约束。

同人可以采用原作人物和设定，但不得把原作正文、标志性段落或具体表达当成可直接复用的素材。文风应描述为可执行的写作特征，不要求复刻原作句子。

## 5. 结束检查

结束前确认：

- 原作范围、Canon 锚点和允许偏离的范围是否清楚？
- 原著参考大纲是否**基于已核实素材**、按用户确认的分卷/区间整理，且未混入臆造 Canon？
- 故事线位置是否唯一且与时间线一致？
- 对应位置的候选同人大纲与节拍表（平行/之前/之后）是否已用户确认并落盘？
- 同人主线是否与「原著参考」轨道分开维护？
- 原创主角线或新增冲突是否能独立成立？
