# 故事连续性维护

本指南供编年史者和直接承担事实整理任务的主 Agent 使用。只做大纲规划或讨论尚未发生的剧情时，不据此更新已发生的故事状态。

## 选择 reference

按任务选择附件；正文提取再按当前工作区的作品类型与路径规则选择，不能因为读取了跨作品参考资料而切换：

| 任务 | Reference |
| --- | --- |
| 建立、查询、调整或清理人物及实体关系 | `references/relations.md` |
| 小说正文事实提取，使用章节路径 | `references/novel.md` |
| 剧本正文事实提取，使用 `scenes` 路径 | `references/screenplay.md` |

复制 `<skill_resources>` 中的 `reference-list` 调用列出附件，再用 `reference-get` 读取选中文件；`name` 使用「故事连续性维护」，`path` 使用目录返回值。开始提取和写入前必须读完对应 reference；已读取且仍在上下文中的附件无需重读，不预读全部附件。类型或处理范围不明确时先读取定位，仍无法确定再询问。

单独管理关系时只需读取关系附件与相关实体、证据，不必执行正文提取、章节总结或重写 `story_state`。正文提取中涉及关系操作时，再追加读取关系附件。设定阶段可以按用户要求建立关系，但必须标明设定依据，不当作正文已发生的事实。

## 正文事实维护原则

- 先读已有 `story_state` 和任务指定的正文；只提取有原文依据的事实，不把大纲计划、角色谎言或猜测当成已经发生的事实。
- 只处理本次指定范围，先查已有实体，合并仍有效的信息，避免重复创建。
- `story_state` 是累积状态文档。通过 `Write {"path":"story_state","fields":{"content":"<当前故事状态 Markdown>"}}` 更新，在正文中如实注明覆盖范围。
- 返工早期内容时修正受影响事实，保留后续仍成立的状态；共享实体的动态状态也不能直接退回早期时点。无法确定后续影响时注明待核对，不编造结论。
- 不改写正文或大纲。完成后简要报告处理范围、实际更新和未解决的连续性问题；工具失败不得声称已保存。

## 正文事实维护顺序

1. 读取已有 `story_state`、任务指定正文与必要实体，核对范围和证据是否完整。
2. 按对应 reference 提取事实；涉及关系操作时先读取 `references/relations.md`，遵循其中的类型、方向、证据与去重规则。
3. 合并实体变化、处理已核实的关系变化，按 reference 更新章节总结或剧本状态。
4. 汇总实际成功的写入与待核对项。局部处理不能声称覆盖全书或全剧。
