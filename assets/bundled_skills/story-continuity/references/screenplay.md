## 剧本事实提取

处理当前剧本中任务指定的场次。输出落在 `story_state`、已有共享实体字段及关系证据；同时整理场次短标题、情绪与事件。

### 读取与证据

1. 按任务给出的场次路径读取场次信息、`/elements` 与 `/cast`；`has_more=true` 时继续读取，收齐正文后再提取。未给场次时，用季、集 listing 定位，显式提供目标 `episode_id` 读取场次列表，再复制真实场次 ID。
2. 单集的大纲、节拍与场次梗概只辅助理解意图，事实以完整正文元素为依据。`character` 元素标识后续台词说话者，使用其 `character_id`；动作、台词、画外音与转场按原顺序理解，人物说出的内容不自动等于客观事实。
3. 闪回、梦境、插叙和角色回忆须标明故事内时点，不按场次排列推断现实中的先后。材料不足时保留不确定性。
4. 只读任务所需的人物、地点、物品、技能和势力；关系创建前先 Read 核对含 ended 的已有记录，GraphSearch 只看当前生效网络。跨作品参考不能作为当前剧本已发生的事实；与当前正文或已确认设定冲突时记录双方来源，交由编排者向用户确认。外部实体、章节或场次 ID 不能用于本作的关系、证据或伏笔位置。

### 共享实体与关系

- 角色：稳定经历写 `biography`、稳定视觉特征写 `appearance`、声线或习惯动作写 `description`；`personality` / `behavior_tags` 需要明确或重复证据。位置、伤势、持有物、目标和已知信息写 `current_state`。更新前合并已有内容，不覆盖后续仍成立的状态。
- 人物别名、地点、物品、技能和势力：先查再创建，保留已有有效项；无姓名且不影响剧情的背景人物不单独建档。
- 关系：使用当前作品的实体 ID；场次证据填真实 `scene_id` 与 `proof`，不填 `chapter_id`，不为未来场次编造 ID。亲属关系只存规范方向，关系结束时用 Write 将原记录设为 ended，提供 reason 与 proof；恢复沿用原 ID。
- 伏笔：先查 foreshadowing，再合并铺垫、回收和状态；位置分别使用 setup_scene_id、payoff_scene_id，复制真实场次 ID，null 可清空。需要字段契约时 Read /_schema/foreshadowing。
- 不写章节专属字段，也不写场次的 brief / tension；不以修改场次梗概代替写后总结。

### 场次写后整理

收齐本场完整正文后，使用 `scenes/{scene_id}/title`、`/emotion`、`/events` 分别写入：

- `title`：用简短标题点明本场主要事件，帮助区分重复地点的场次。
- `emotion`：本场主导情绪的字符串数组，标签简短、不重复；材料不足时可为空。
- `events`：按本场发生顺序列出事件，每项包含 `title`、`summary`，以及可选的 `state_change`，说明事件造成的变化。无状态变化时不强行填写。

事实以正文为准，不根据尚未写入正文的大纲或梗概编造事件。正文返工后重新核对上述三项；核对完成前保留旧结果。

### 当前故事状态

正文注明“截至第几季、第几集、第几场”，并附对应场次路径；仅整理部分场次时明确范围，不声称覆盖全剧。

建议保留以下内容，已有快照可以沿用原结构：

- 时间与空间：故事内时点、主要人物位置。
- 角色硬状态：伤势、消耗、关键持有物、当前目标。
- 信息边界：谁知道、谁不知道、谁误判；区分观众已知与角色已知。
- 未结冲突与悬念：仍在生效的矛盾、铺垫和未兑现承诺。
- 待核对：证据矛盾或本次范围无法确认的事实，附具体场次来源。

全局或无独立字段的事实写入 `story_state`。不生成小说的章末钩子、字数密度或章节张力账本。
