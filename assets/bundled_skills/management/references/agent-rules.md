# 智能体规则管理

用于管理当前小说的用户自定义规则。AgentRule 是会自动注入后续聊天 prompt 的长期约束，适合保存用户确认过的写作偏好、禁忌、章节规格、风格边界和稳定工作要求。

必须先区分三类内容：

- **AgentRule / agent rule / 用户自定义规则**：长期约束 AI 后续怎么写、怎么判断，例如“章节正文目标 4000-5000 字”“不要写降智反派”“第三人称单主角视角”。这类内容用 Run 的 `agent-rules` 命令管理。
- **AgentSkill / agent skill / AI 技能**：可按任务加载的一套流程，例如“章节节奏审稿”“人物行为推导”。这类内容用 Run 的 `agent-skills` 命令管理，不要写进 AgentRules。
- **小说内规则 / 世界观规则 / 能力规则**：故事事实或设定，例如“魔法需要消耗灵力”“主角的火焰不能点燃金属”。这类内容通常应写入世界观、角色、物品或正文资料；只有当用户明确要求 AI 后续创作必须遵守时，才可提炼成 AgentRule。

如果用户只说“新建规则”，但无法判断是 AgentRule、AgentSkill 还是小说设定，先问清楚，不要直接调用 Run。

## 触发条件

满足任一条件时使用：

- 用户要查看当前规则列表，或读取某条规则全文。
- 用户要把偏好、禁忌、风格、章节字数、叙事视角、更新节奏保存成长期规则。
- 用户说“以后都这样”“记住这个规则”“按这个规则写”“不要再出现这种问题”。
- 用户要修改、改名、启用、停用或删除某条已有规则。
- 现有规则冲突，用户要求整理或合并。

不要在以下场景使用：

- 用户只是要完成一次临时写作任务，且没有表达长期保存。
- 用户要创建的是一套可调用流程，应转为 AgentSkill 管理。
- 用户要保存的是小说资料本身，应写入对应资料，而不是只写 AgentRule。

## 工作流程

### 1. 先确认是否要长期保存

AgentRule 会影响后续聊天，不适合保存临时指令。判断不清时先问用户：

- 这条规则是否要长期应用到当前小说？
- 是约束 AI 的写作/判断方式，还是小说世界观资料？

用户确认前，不要写入。

### 2. 先列出现有规则

创建、更新、删除前，先用 Run 查看当前规则，避免重复和冲突：

```text
Run {"command":"agent-rules","subcommand":"list","options":{}}
```

需要查看某条规则全文时：

```text
Run {"command":"agent-rules","subcommand":"read","options":{"name":"章节字数"}}
```

`agent-rules` 按规则名称读写，不按 id 操作。名称必须与列表或用户确认的标题一致。

### 3. 判断创建、更新还是合并

使用以下判断：

- 已有同名规则：用 `update`。
- 已有同类规则但标题不同：先读取旧规则，判断是合并、改名还是新建。
- 新规则与旧规则冲突：指出冲突，让用户选保留哪一条；不要平均处理。
- 没有同类规则：用 `create`。

不要把不相关的约束塞进一条规则。每条规则只管一个维度，便于后续修改和冲突排查。

### 4. 写好规则内容

一条好的 AgentRule 应该：

- 可执行：AI 能判断是否遵守。
- 单一职责：只约束一个维度。
- 有适用范围：说明适用于全文、章节正文、大纲、对话、角色行为或世界观。
- 不含空话：避免“写好一点”“更自然”“更有爽感”。
- 不泄露底层错误或工具细节给用户可见文本。

示例：

```text
章节正文目标字数为 4000-5000 字；除非用户另行指定，允许上下浮动 10%。
```

```text
正文使用第三人称单主角视角；不得写出 POV 角色无法感知或推断的信息。
```

```text
反派行为必须符合其利益、信息边界和性格底色；禁止为了推进剧情让反派临时降智。
```

### 5. 创建规则

用户确认后，用 Run 创建：

```text
Run {"command":"agent-rules","subcommand":"create","options":{"name":"章节字数","content":"章节正文目标字数为 4000-5000 字；除非用户另行指定，允许上下浮动 10%。"}}
```

创建后默认启用。需要创建但暂不启用时：

```text
Run {"command":"agent-rules","subcommand":"create","options":{"name":"章末钩子","content":"章节结尾应保留明确钩子或情绪缺口。","enabled":"false"}}
```

也可用 `disabled: true` 创建为停用状态。

### 6. 更新、改名、排序、启停

更新内容：

```text
Run {"command":"agent-rules","subcommand":"update","options":{"name":"章节字数","content":"章节正文目标字数为 4500-5500 字；除非用户另行指定，允许上下浮动 10%。"}}
```

改名：

```text
Run {"command":"agent-rules","subcommand":"update","options":{"name":"章节字数","new-name":"章节正文长度"}}
```

停用或启用：

```text
Run {"command":"agent-rules","subcommand":"update","options":{"name":"章末钩子","enabled":"false"}}
```

```text
Run {"command":"agent-rules","subcommand":"update","options":{"name":"章末钩子","enabled":"true"}}
```

调整排序：

```text
Run {"command":"agent-rules","subcommand":"update","options":{"name":"章节正文长度","sort-order":"0"}}
```

### 7. 删除规则

只有用户明确要求删除时才执行：

```text
Run {"command":"agent-rules","subcommand":"delete","options":{"name":"章节字数"}}
```

如果用户只是“不想暂时使用”，优先停用而不是删除。

### 8. 保存后回报结果

Run 成功后，简短说明：

- 创建、更新、停用、启用或删除了哪条规则。
- 当前规则是否启用。
- 如果是合并或冲突处理，说明最终保留的约束。

Run 失败时，直接报告失败原因。不要说“已保存”，也不要改用普通回复代替持久化。

## 冲突处理

发现冲突时按这个格式向用户说明：

```text
发现规则冲突：
旧规则：每章 2500-3000 字。
新要求：每章 4000-5000 字。
请确认后续按哪一个执行。
```

用户确认前，不要覆盖旧规则。若冲突影响当前任务，先暂停写入，只处理这一处取舍。

## 常见误判

- “以后所有章节不要写降智反派”是 AgentRule。
- “帮我设计一个魔法规则：火系法术怕水”通常是小说设定，不是 AgentRule。
- “以后审稿时按六步检查”通常是 AgentSkill，不是 AgentRule。
- “把本书设定里主角不能复活这条记住”可以先写入世界观；如果用户强调后续创作必须遵守，可再提炼成 AgentRule。
