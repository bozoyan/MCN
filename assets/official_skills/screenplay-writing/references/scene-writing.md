# 场次写作

交付人物真正做了什么、说了什么以及造成的变化。场景的戏剧功能决定写法，格式和制作细节为内容服务。

## 准备直接上下文

读取本次场次、大纲或节拍、相关人物，以及衔接所需的前场正文。续写时核对上一场的最后行动、知情状态和物件归属；已有完整正文时，以当前正文为准，不拿旧梗概替代。

用户已给足方向就开写。只有缺口会改变主角、核心选择、结局或改编边界时才提问；普通措辞、动作呈现和场景节奏可直接处理。

## 写场

1. 明确这场为何存在、谁想得到什么、为什么难以得到，以及结束后什么会不同。以冲突推动的场景写出策略与反制；过渡、氛围、余波或仪式场景按其实际作用组织，不硬造对手。
2. 从行动已经有压力的地方进入，保留理解所必需的空间信息。角色的下一步要回应刚发生的事，不能为了执行大纲而忽视现场变化。
3. 用可见动作和可听声音承载必要事实。心理活动可通过行为、对白、声画关系或符合既定形式的旁白表达；不要把人物真实想法写成摄影机能直接拍到的事实。
4. 场景达到预定结果后及时离开。需要留白就让余波发生，不追加同义解释来证明观众看懂了。

用户给定时长时，先安排本次范围内的行动、对白交锋与转折，再展开正文。整集要求按整集核对；委派部分场次时说明其负责范围，不把整集时长套给每一场。不得把时长要求换成固定字数指标。

写完后依据实际正文核对内容容量。按连续表演段给出有依据的粗估区间，区分发声、独占动作与可重叠部分；不从目标倒推动作耗时，不把总字数、版面页数或分镜计划换算成正文时长。明显不足时，展开被概括掉的交锋、行动、选择或后果；不得靠增加描写字数、拖慢表演或承诺“后期补满”交差。写入成功和粗估接近目标，都不能单独证明时长达标。

场景因果、证据与选择的细节见 [场景手艺](scene-craft.md)。用户或作品智能体规则给出时长要求，或涉及多人动作、声音安排、AI 视频制作约束时，读取 [表演与制作约束](production-constraints.md)；有时长要求时，交付前按其中方法核对。对白是主要难点时读取 [对白修订](dialogue.md)，普通台词无需额外加载。

## 写入与局部修改

- 在剧本工作区读写时先加载「剧本工具使用规范」。场景标题由场次字段表达，正文写入动作、人物提示、对白等结构化元素；不把整场 Markdown 塞进某个动作元素。
- 用户只要讨论或展示文本时按所需格式交付，不因此建季、建集或修改原作。用户要求正式写场时完成目标正文写入，不以梗概或聊天草稿代替。
- 修改一个动作或一句台词，连读其前后节拍；检查位置、知情、称谓、说话人和持物是否仍一致。只改获授权范围，保留未改元素与已有身份。
- 完成前核对实际写入范围。写后事实整理遵循主 Agent 既有流程，不在此另建自动审查或文件流水线。
