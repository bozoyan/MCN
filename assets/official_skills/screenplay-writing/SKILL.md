# 剧本写作

将故事材料、创作方向或已有稿件落实为本次需要的改编方案、分集大纲、场次正文、对白或审稿意见。直接进入用户指定的环节；已确定的方案继续使用，不为改一句对白重做改编与分集，也不把审稿自动扩大成改稿。

## 确定任务与上下文

先确定目标作品、材料版本、本次范围和交付物。读取直接相关的原文、已有方案、人物与前后文，以当前实际稿件为准，不拿旧梗概代替正文；材料不全时说明已读范围和结论限制。

用户已给足方向就执行。只有缺口会改变主角、核心选择、结局、核心关系或改编边界时才提问；普通措辞、动作呈现和局部节奏可直接处理。分集规划所需的集数与时长按对应附件处理，不自行假定。

原文事实、推断、候选改法与已确认方案分别表达。未获采用的构思不写成既定事实，局部修改不扩大到整季或原作。

| 本次任务 | 先读 | 按需深入 |

| 规划分集、单集节拍，压缩、扩展或重排剧集 | [分集规划](references/episode-planning.md) | [单集设计](references/episode-design.md)、[系列与连续性](references/series-continuity.md) |
| 编写、续写或修改场次正文 | [场次写作](references/scene-writing.md) | [场景手艺](references/scene-craft.md)；有时长要求、多人动作或制作约束时读 [表演与制作约束](references/production-constraints.md) |
| 打磨局部对白、潜台词、交锋与人物声音 | [对白修订](references/dialogue.md) | [对白手艺](references/dialogue-craft.md)、[局部修订示例](references/revision-example.md) |

只加载本次环节所需附件，执行对应环节前读完，不预读全部内容。使用 `<skill_resources>` 提供的 `reference-list` / `reference-get` 调用，`name` 使用「剧本写作」，`path` 原样复制附件目录中的路径；已在上下文中的附件无需重读。

混合任务按实际需要衔接：例如“把这几章改成两集并写第一场”，先完成改编取舍与分集，再写指定场次。普通写作保留必要自检；用户要求专门审稿时才进入审稿流程，自检不声称独立复审。

## 写入与交付边界

- 读写剧本工作区前加载「剧本工具使用规范」对应附件，沿用其资源和操作契约。方案、大纲、场次梗概与正文各归其位，不把梗概当作正文，也不把整场 Markdown 塞进一个动作元素。
- 只讨论或展示文本时不建季、建集或修改原作；要求正式写入时完成目标资源写入并回读核对，保留已有身份与未改内容。小说对白修订保留原有叙述格式。
- 只审查时给具体位置、证据、影响和修订目标，不直接改稿；获准审改时才修订指定范围并核对相邻上下文。缺少正文、原著或实测媒体时，不宣称对应部分已验证。
- 目标时长、正文粗估与媒体实测分别报告。整集按整集范围核对，不用总字数、分镜计划时长或写入成功证明正文达标，不靠拖慢表演或重复内容凑时长。
- 分镜、视觉参考、视频提示词及生成结果返修使用「剧本制片」。写作阶段可以指出制作难点，但不因此自动出图、配音或生成视频；制片需改剧情时仍须遵循作者授权。
- 写后事实整理遵循主 Agent 既有流程与「故事连续性维护」，不在本技能另建自动审查或事实写入流水线。
