# 地图设计指南

目标是让读者理解故事发生在哪里、空间为何重要、人物如何移动。适用于任意题材及混合题材；从实际世界规则和阅读任务推导设计，不按有限的题材分类套模板。自然地理只在适用时作为基础。面向 `gpt-image-2` 编写内容提示词；本技能负责设计方法与地点校验；草稿参数和提交按 `Run help map` 执行，图片由制图师生成。纯设计讨论无需提交草稿。

## 按需读取附件

通过 `<skill_resources>` 提供的 `reference-list` / `reference-get` 调用读取，`name` 使用「地图设计指南」，`path` 原样复制附件路径。

| 附件 | 何时读取 |
|---|---|
| [references/cartography.md](references/cartography.md) | 首次设计、推荐或调整画风时读取“按小说类型推荐画风”；整体重排时再读版面、标题和图例规范 |
| [references/prompt-examples.md](references/prompt-examples.md) | 需要完整版面提示词、空间约束的写法或局部改图示例；示例不限定题材 |

修正一个地名或一条道路时按下方编辑流程即可，不必加载全部附件。附件用于构思，不把整份附件、引用链接或解释文字塞进出图 prompt。

## 先确定范围和地点真源

使用 Read 读取目标地点，再读取 `/locations` 并按分页取全目标子树，核对名称、ID、父子关系、描述与已知空间关系；需要补足背景时只读相关设定。ID 和资源路径从响应复制。已有地点够用时直接设计；缺失信息会实质改变方案时先提出具体问题，等回答后再创建地点或提交。

区分已有事实、用户授权的新设定与纯视觉填充。无名丘陵、树林可作为不影响情节的视觉细节；新城、新国、改变交通或疆界不属于装饰，不为画图另造一批地点。用户明确授权“你决定”“自行设计”时，简要说明方案后按父级到子级创建；其他新增设定先给方案等待确认。子地点地图只规划它的子孙地点，不创建或修改范围外的地点。创建或修改后再次读取 `/locations`：图中每个具名地域、城市、地标、河流和道路都须在目标子树中有记录，标题可用目标地点本身；prompt 不能替代地点数据。

先把事实压缩成空间约束：谁在谁的哪侧、属于哪个空间、隔着什么、通过什么抵达。地点树的父子关系用于组织地点，不能单凭它断言洞天物理上位于宗门地下，或两个相邻星区能够直航。数量、方向或归属相互冲突时先解决，不让图片模型替用户裁决。

若任务涉及秘密地点、未知地域或变化中的疆域，区分作者全知图、截至某章的读者图与书中人物持有的地图；这会改变可画内容时先确认。不要默认把终局版图、隐藏入口或未来路线画进当前阶段。

## 地图的默认结构

新设计默认使用“上方标题 → 中间主图 → 下方阅读辅助”的完整图面。已有图局部修改时保留原版式；用户要求无字底图、残缺古图等特殊形式时按用途调整，不强加完整要素。

| 要素 | 默认规范 |
|---|---|
| 主标题 | 顶部居中，仅出现一次。用目标地点的正式名称，加必要的范围或用途，如「澄湾地区图」「旧馆一层平面图」；已有合适图名直接沿用 |
| 副标题 | 可选。只写会改变理解的已知年代、楼层、阶段或视角；没有就省略，不造纪年、编制单位或宣传口号 |
| 主图 | 画面主体；放地形／空间、地点、通路、边界与地名。先留好标题及辅助信息的位置，不让装饰或图例盖住关键内容 |
| 图例 | 默认在下方左侧，紧凑排布“符号样本＋含义”。非直观符号、有含义的颜色／线型必须解释；全图已用直接文字讲清时可省略，不留空框 |
| 方向 | 有方向意义时在主图空白角落放小指北标或已知方向说明；不在层级图、拓扑图上伪造东南西北 |
| 尺度说明 | 默认下方右侧。有可信距离与统一比例依据才画比例尺；非等比例图标注「非等比例示意」，不能用任意刻度装饰 |
| 定位／局部附图 | 按需加入有标题的小图，说明位置、放大局部或不同空间。须与主图边界分明，并标清对应范围；不重复主图充数 |

标题文字、图例条目、方向和尺度说明都要在 prompt 中写明；它们是画面内容，不是工具新增字段。详细取舍、底部放不下时的侧栏布局及图例一致性检查见 `cartography.md` 的“图面结构规范”。

## 编写完整的内容 prompt

使用中文短段落，按需写以下内容，不填空泛的“史诗级、8K、极致细节”：

- **版面与文字清单**：先确定主标题、可选副标题、主图、图例和辅助要素的具体内容与位置，再写地图内部。逐字列出标题、必要注记和每个图例条目的“符号样本＋含义”；未使用的模块省略。
- **用途与视角**：小说阅读用地图，16:9 横版；目标范围、尺度和表达方式。地表图没有既定朝向时可声明上北下南；星区示意图不要强加地球经纬度，已有图保留既定方向体系。
- **空间骨架**：按设定选择大陆与海洋、断裂浮陆、独立界域或星区节点。先整体后局部，用明确相对位置；跨界图说明分区之间是否连续，航路示意图说明位置与连线不代表真实距离。
- **地点与连接**：列出必画名称、所属空间和位置；道路、御空航线、传送门或跃迁通道写清端点、方向及已知限制。连接关系用相应符号表达，不把传送通道画成穿越山海的实体公路。不要给同一地点两套位置。
- **标签与层级**：地名加引号并逐字保留；地域名、城镇名、地标名分层。标签靠近所属对象，背景留出安静区域，不能跨界造成归属歧义。中文地名是画面内容，不能写 `no text`。
- **保留与排除**：指定不得改变的地形和关系；排除额外地名、乱码、重复标签、无依据的数字比例尺、装饰遮挡和无关人物。按任务添加限制，不列与地图无关的禁词清单。
- **参考图职责**：有参考图时写清继承什么、重画什么，见下方。草稿的 prompt 会完整替换默认内容提示词，不能指望默认模板补回缺失要求。

地名与制图文字分开校验：地名须来自地点记录；“图例”“北”“非等比例示意”和实际符号含义等制图文字不需要创建为地点。禁止额外文字时，明确允许已列出的标题、地名、图例与注记，避免把刚要求的图例也禁掉。

prompt 中不要写画风；材质、配色、笔触与字体风格通过 `style` 或 `custom_style` 单独提交。标签大小、层级、可读性以及参考图的用途仍写在内容 prompt 中。

## 参考图和局部编辑

- **修改当前图**：确有当前图片且用户要在其基础上改动时，传 `reference_current_image: true`。写明 image 1 是当前图，列出本次唯一或少量改动，并列出保留的海岸、疆界、地点位置、名称、道路端点与朝向。每轮重新说明关键保留项，不只写“同上”。
- **沿用父地图画风**：父图只提供画风、配色、线条与地名字体，子图必须按自己的范围重新构图；不能把父图的整个大陆、地名或布局复制下来。子图仍须遵守文字设定中已知的朝向、河岸、入口或航路关系；独立构图不等于重设世界事实。
- **图片顺序**：实际附图顺序是当前图在先、父图在后。两张都使用时 image 1 为当前图，image 2 为父图；只有父图时它是 image 1。只在已确认附图状态时写死编号；状态不明时条件式写明“若有上层地图参考，仅用于视觉风格，不继承地形和地名”。
- 没看到成图时只能检查设计约束，不能声称已核实汉字或地理正确。拿到成图反馈后先分清是地点资料、布局还是文字问题，针对性修改，不自动循环出图。

## 风格与出图建议

画风建议是地图设计的一部分，不能只列出预设让用户自行选择，也不能把所有小说默认画成现代图册。读取相关作品信息与用户要求，结合**小说类型、作品气质、世界的时代／技术背景、地图尺度与用途**给出一条主建议和一句具体理由。题材已知时不重复询问；缺失时先从现有设定推断并说明，只有会导致明显不同方向时再问。

- 用户明确选定画风或交接要求保留时，沿用该选择；调整建议可以说明，但不擅自替换。只要求改画风时保留标题、图例、地名、布局与地理关系。
- 用户让你选画风时，按 `cartography.md` 的题材建议和作品气质选择。内置预设能表达目标就使用它；需要细化地形表现、建筑质感、媒介或气氛时用 `custom`，不要求先用预设失败一次。
- 有父图或系列风格时优先考虑一致性；不把一个默认预设的存在当作用户对它的审美认可。交接要求保留与用户新要求冲突时，以用户新要求为准。
- 同一题材可以有不同气质；表格是起点，未列出的类型和混合类型按相同维度推导。避免把“清晰、可读”一律翻译成“低饱和、少细节、圆点地图”。
- 自定义描述集中放在 `custom_style`，内容 prompt 不夹入另一套画风。提交前检查圆点／建筑符号、平面／浮雕地形、纹理和字体等要求是否相容；按选定表现方式保持图例对应，不借画风调整重写世界设定。

推荐可写成：“这部作品偏……，本图用于……，建议……；用……表现……，同时保留……的可读性。”无需每次列出全部预设或等待一次额外选择；已授权自行设计时直接将建议落实到草稿参数。

参数取值、默认档位和参考图开关以 `Run help map` 为准。构图探索可用较低质量；中文小字或密集标签、用户明确要求精细成图时考虑提高质量。

先解决空间与标签冲突，再提高质量或尺寸。通常从 `2k` 开始；超密内容优先规划子地图，不承诺把所有地名挤进一张大图。是否省略具名地点或新增子地图按用户要求决定。

## 校验和提交

提交前核对：

- 必画地名是否逐字来自地点记录，数量与父子关系是否一致，是否只覆盖目标范围？
- 标题是否准确说明对象和范围？副标题是否有事实依据？图例样本与主图的形状、颜色、线型和方向是否逐项对应，是否有缺项或无用项？
- 方位、水系、疆界和路线能否同时成立？超自然例外是否有设定依据？
- 物理邻近、通行连接、势力影响是否被区分？跨界或跃迁条件是否遵守设定，是否泄露当前视角不该知道的内容？
- 标签是否各有所属，画面是否给文字留出空间，是否把装饰误当主内容？
- 方向与尺度是否适用于本图？附图的范围和独立尺度是否明确？图面文字是否全部落在留白内、未被裁边或彼此遮挡？
- 画风是否只在独立参数，参考图职责是否完整，编辑是否保护无关内容？
- 风格建议是否依据本作类型与气质，是否解释了选择理由？自定义描述是否可直接执行，是否与内容 prompt 的表现要求矛盾？
- 是否尊重用户选择的风格和档位，是否仍有影响方案的未答问题？

设计交付包含完整内容 prompt、独立画风建议及未验证项。用户需要提交制图草稿时，按 `Run help map` 只提交一次 `Run map draft`；成功后说明草稿已提交、可在制图师审阅并生成，不把提交描述为出图完成。只讨论方案或提示词时直接交付设计，不调用生成工具。
