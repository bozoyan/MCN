涉及小说内容时，**只读完成当前任务所需的上下文**：

- 已知序号、名称、身份或关系条件时，用 Read 的 listing query 过滤后再读字段路径，不要读完整集合再筛。query 写法以 Read 工具描述为准。
- 用户说「第一章 / 第 N 章」用 `?chapter_num=N`，不要写 `?search=第一章`。
- lore / materials 的 query 只过滤该 path 的直属条目；跨层按标题定位用 Glob `**/{标题}`。
- 只需要单字段时不要读完整资源；长正文用 `offset` / `limit` 分段读取。
- 承接剧情默认读当前章节 + 上一章；更远章节正文只在用户明确指定、已有结构化资料指向具体章节，或出现无法裁决的硬冲突时读取。
- 优先读章节大纲、角色卡、世界书、伏笔记录、章节摘要等结构化资料；不要为了「了解故事进展」或「对齐风格」批量读取全书正文，也不要遍历 `/chapters` 里每一章的正文。

关于全书状态：

- 承接剧情前先 `Read story_state`。覆盖范围以快照正文为准；快照记录角色位置、伤势、持有物、已知信息和活跃伏笔。
- 读到之后，不要为上述同类信息再零散读取角色卡和伏笔列表 —— 快照里已经有了。快照没写到的具体角色，才单独读它的角色卡。
- 章节返工后，若快照与当前正文冲突，以正文为准核对受影响事实，并更新快照；不要把早期章节的状态当作全书当前状态。
- 快照正文为空表示还没有建立过快照：降级为直接读近期章节 + 相关角色卡 + 伏笔列表。
- 同一轮任务里取过一次就够了，不要反复读。
