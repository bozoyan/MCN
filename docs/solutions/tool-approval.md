# 工具权限与审批方案

> 本文整理 [Agent 工具实施合同](short-drama/agent-tools.md)、[分层权限方案](short-drama/agent.md)及后续讨论，作为通用工具审批的独立设计。命令参数、后台运行、去重、文件读取等业务合同以上述两份文档为准，本文只记录与审批交界的部分。

## 1. 目标与边界

工具解析出具体操作后，把所需权限与执行函数一起交给共同执行流程。共同流程完成规则查询、审批、执行前复核，再调用业务函数。框架不分析提示词，也不从工具名或命令名前缀猜测权限。

- 模型生成图片、视频、音频统一通过 `Run` 发起，命令按业务分组。普通资源的创建、配置编辑、查询继续使用 Create／Write／Edit／Read。
- 本期启用 `generation.image`、`generation.video`、`generation.audio`、`files.read` 四类能力权限，默认均为 `ask`。四类能力全部由 Run 命令承载；普通内容编辑、剪辑、导演本地渲染和导出不增加审批动作，其已有业务校验、文件访问和取消约束继续有效。
- 工具定义保持静态。权限、渠道配置和平台能力不会改变发给模型的 schema；内部权限元数据不写进模型可提交的参数。
- Windows、macOS、Android 共用权限模型、设置和审批语义。平台未实现的媒体功能返回明确错误，不能因为提供了 Run 命令就宣称已支持。

模型生成不通过 `Create /clips/{clip_id}/generations` 发起，该集合只保留只读历史语义。持久任务取消归入 Run 控制入口，不新增 `Write .../cancel` 执行动作。导演／画布的 `Write output` 属于本地渲染及输出，不在本方案范围内。

## 2. 名称与身份

| 名称 | 含义 | 示例及生命周期 |
|---|---|---|
| 工具名 | 模型调用的顶层工具 | `Run`、`Write` |
| `command`／`subcommand` | Run 的业务分组及动作 | `production`／`generate-image` |
| `operation` | 具体操作类型的固定名称 | `production.generate-image`；调用一百次也相同 |
| 权限能力 | 多个业务操作共同需要的授权 | `generation.image`；本期写入权限规则表的 `action` 列 |
| `key` | 保留给以后更细粒度的权限控制 | 本期不占用，不新增参数、列或匹配行为 |
| 工具调用 | 模型的一次工具调用 | 同一个调用可以启动多个独立操作 |
| 运行 | 一次受跟踪的具体执行 | 每个独立运行不同，用于查询、等待和取消 |
| 审批请求 | 一次冻结后等待用户决定的请求 | 每个请求身份独立；同一工具调用产生的多个审批互不影响 |

`operation` 描述操作类型，不能与具体执行、审批或生成任务的身份混用，也不能从运行类别等其他字段推断权限。`request_id`、`task_id` 属于业务去重与持久任务身份，见 [agent-tools 合同](short-drama/agent-tools.md)，不参与授权判断。

## 3. Run 命令与权限能力

| 命令 | 权限能力 |
|---|---|
| `Run production generate-image` | `generation.image` |
| `Run production generate-video` | `generation.video` |
| `Run production generate-audio` | `generation.audio` |
| `Run character generate-avatar` | `generation.image` |
| `Run character generate-photo` | `generation.image` |
| `Run item generate-photo` | `generation.image` |
| `Run files read` | `files.read` |
| `Run ffmpeg probe／execute` | 每个显式输入匹配 `files.read` |
| 导入外部媒体 | `files.read` |

各命令的参数合同和校验见 [agent-tools 合同](short-drama/agent-tools.md)。生成权限通过不能跳过模型能力、数量、时长、参考输入和业务归属校验。人物、物品生图只有上表一个入口，不保留绕过审批的旧路由。

落地时涉及以下两项先单独确认：

- 修改工具整体描述或 input schema 中的参数 `description`，先向用户提交拟修改文案并获确认。
- 修改打包技能前，核对实际发布记录及标签中的技能版本，决定递增 `version` 还是并入未发布版本，并同步 Debug 数据库中的官方安装快照。

## 4. 执行结构

### 4.1 Run 命令表

Run 由一张命令定义表路由，同一条记录同时声明 `operation`、权限能力和执行绑定，权限不能散落在各命令内部单独判断。其他工具不经过命令表；以后某个资源操作需要审批时，再为资源操作增加同样的内部权限声明，复用路径解析，不另造路径分类器。

参数规范化只做一次，授权和执行使用同一份规范化结果，不能各自解释原始参数。命令未知或声明不完整时明确拒绝，不降级为无权限执行。

### 4.2 命令定义

这是内部定义，不是模型参数，也不是数据库记录。

| 字段 | 合同 |
|---|---|
| `operation` | 注册时确定的操作类型，如 `production.generate-image` |
| `permission` | 显式声明 `none` 或 `required(capability)`；未知能力或缺失声明是注册错误 |
| `prepare` | 接收已规范化输入和可信上下文，返回准备结果；`none` 命令直接执行，不经过准备 |

`none` 只表示没有本期新增的动作审批，不跳过工具模式、目标归属、锁定、业务校验或操作系统权限。

### 4.3 准备结果

| 字段 | 合同 |
|---|---|
| 目标 | 实际业务对象或规范化文件目标 |
| 权限上下文 | 从真实业务对象解析的作品、集、授权会话 |
| 审批摘要 | 给用户看的渠道、模型、规格、目标、参考输入及必要上传等事实 |
| 冻结请求 | 后续实际使用的参数及输入身份，不能被 UI 或模型再修改 |
| 目标复核 | 执行前重新准备一次并与冻结请求比较，不一致返回 `conflict`，不提交副作用 |
| 执行 | 绑定冻结请求，不重新读取当前配置替换已批准请求 |

权限能力来自命令定义，不由准备结果、模型参数或业务执行函数临时改成其他能力。

冻结请求保证用户批准时看到的配置就是实际提交的配置。审批可能挂起很久，期间用户可能在界面修改节点，或模型在同一回合并行 Write 修改模型、时长、参考输入；不冻结会让批准一张便宜图片变成提交另一份更贵的请求。

准备阶段可以查询业务配置、读取应用素材库内文件的身份与媒体元数据（如时长、规格），用于审批摘要和比对。正文读取、解码、抽帧、复制参考内容、上传及生成放在获准后的执行阶段。应用素材库之外的文件读取都属于 `files.read`，准备阶段只解析路径和文件身份。

生成或渲染对已冻结业务输入的必要内部读取，在该操作已批准的范围内执行，不给每次内部读取再弹审批卡。

### 4.4 共同执行流程

```text
工具输入
  → 工具模式／取消检查
  → 规范化、查命令表、静态校验
  → 命令定义
      ├─ none：直接执行
      └─ required：
          准备（失败直接作为工具错误返回，不登记运行）
              ↓
          登记运行
              ↓
          查规则／等待真实用户决定
              ↓
          目标复核 + 最新权限复核
              ↓
          执行业务并返回真实结果
```

- 需要权限的操作一律登记为运行，包括 `background=false` 的同步操作；审批、取消和运行记录只有这一条路径。
- 准备只做查询和元数据探测，放在登记前；运行从登记起就带有真实目标与作用域。
- 工具模式和取消检查先于审批，不询问用户批准一个当前模式不能执行的工具。
- 需要保护的正文或媒体预览在授权后读取，事件和变更记录不能提前完成受限读取。
- 子 Agent 和 Codemode 的真实子调用走同一流程。本期不开放 Codemode 的 Run；Codemode 不能借 Create／Write 发起模型生成。

## 5. 规则匹配与未来扩展

### 5.1 本期：权限能力与作用域

本期规则的 `action` 只使用四个能力名。对一次请求，依次查询 session、episode、work、global 的有效规则；第一条匹配规则决定 `allow`／`ask`／`deny`。都没有则使用动作默认值，本期均为 `ask`。

- `allow`：核验目标及最新规则后执行。
- `ask`：挂起当前请求并显示审批卡。
- `deny`：返回 `permission_denied`，不执行受保护操作。

规则是用户可覆盖的偏好，局部 allow 可以覆盖全局 deny，不加入隐藏的 deny 优先算法。无有效 episode 上下文就跳过该层。权限读取失败、未注册动作、作用域身份不合法或目标失效都不能按 allow 处理。

### 5.2 未来：具体操作覆盖能力规则

命令表现在就保留 `operation` 与能力的映射。以后开放操作级规则时，在 `action` 列保存已注册的操作名称，同一作用域内先查 `operation`，再查能力。本期不开放这套设置。

完整优先级为：

```text
session 的 operation → session 的能力
episode 的 operation → episode 的能力
work 的 operation    → work 的能力
global 的 operation  → global 的能力
能力默认值
```

这是一次决策的覆盖关系，不是连续批准两次。比如全局 `generation.image=allow`、全局 `production.generate-image=ask`，制作图片要询问，人物头像沿能力规则允许。如果会话级能力已设为 allow，则它优先于全局操作规则；先比较作用域，再比较该层规则的精细程度。

能力名与操作名通过静态注册区分并校验，不能由模型任意写入规则。扩展操作级规则无需增加数据库列。`key` 的语义、存储及优先级不在本期定义，也不提前添加空字段。

### 5.3 可信上下文

作品与集从真实业务对象解析，不能用当前打开的页面替代。跨作品操作不能携带来源作品的 session／episode 规则放行目标作品。

会话规则作用于用户发起对话的那个会话。子 Agent 在自己的子会话中执行，但授权沿用发起它的会话：用户在主会话保存的会话级规则对子 Agent 同样生效，子 Agent 也不能通过新会话绕开主会话的规则。运行的管理权（查询、等待、取消）同样归发起会话；不能凭模型传入的 ID 推断管理权。

文件读取仅在有已验证 episode 上下文时匹配集规则。作用域 allow 覆盖范围内后续对其他可访问文件的读取，不只记住当前 path；"仅本次"只覆盖本次冻结的文件和读取方式。系统文件授权仍由平台处理。

## 6. 持久规则与一次性审批

### 6.1 权限规则表

| 列 | 类型及约束 |
|---|---|
| `id` | TEXT，非空，Drift 主键 |
| `action` | TEXT，非空；本期为能力名，未来可容纳已注册 operation |
| `scope_type` | TEXT，非空；global／work／episode／session |
| `work_id` | TEXT，非空；全局为 `''` |
| `scope_id` | TEXT，非空；全局为 `''`，作品级与 work_id 相同 |
| `decision` | TEXT，非空；allow／ask／deny |
| `created_at`／`updated_at` | Drift DateTimeColumn，SQLite INTEGER，Unix 秒 |
| `deleted_at` | 沿现有软删除时间戳写法，0 表示有效 |

唯一索引为 `(scope_type, work_id, scope_id, action)`，包括软删除行。同一身份始终复用一行，恢复继承时软删除，再次设置恢复原行并保留 ID 和 created_at。并发设置依靠事务及唯一索引保持一致。

枚举值、作用域组合和归属在 Dart 校验，不使用 CHECK、外键、表级 UNIQUE 或触发器。规则表不保存工具参数、文件路径、审批请求或运行任务；不使用旧 `ai_auto_approve_tools` 作为授权，也不新增通用持久任务表。迁移按真实发布基线核定。

### 6.2 审批请求与用户操作

每个待审批请求有独立身份，在所属会话内定位。工具调用身份只负责把审批卡关联到聊天中的工具卡，不能作为审批的唯一键。

同一次工具调用发起两个操作时，两份审批可以同时存在。批准一个只执行对应请求；拒绝或取消另一个不影响前者。同类批次可以合并为一份冻结审批，但必须保留全部目标及其作用域，不能通过新请求替换旧请求来实现批量。

审批卡展示操作、实际目标、请求摘要。用户可允许／拒绝本次，或保存到当前会话、集、作品、全局；只显示可信上下文中存在的范围。设置显示生效值和来源，并支持恢复继承。文件读取明确说明内容会提供给当前模型，持久许可明确说明覆盖后续请求。

重复点击只消费一次决定。保存长期规则失败时保持待审批并显示错误，不能回报已允许。批准后重新核对冻结目标和最新权限；收紧为 deny、来源变化或取消均阻止执行。未批准的请求重启后不能恢复成已批准，Agent 也不能修改权限规则给自己授权。

## 7. 与运行、取消、去重的交界

运行状态、Run operations、通知与历史恢复的完整合同见 [agent-tools 合同](short-drama/agent-tools.md) 和 [分层权限方案](short-drama/agent.md)。与审批相关的约束：

- 等待审批的运行状态为 `waiting_approval`，只表示本地已受理，不表示获准执行或上游已接受。
- 等待审批时取消，撤销审批请求后才返回 `cancelled`；停止主回复不撤销后台运行的审批。
- 拒绝或取消不自动重试。查询、等待和取消已有运行或持久任务不需要重新批准。
- 去重命中不重复审批：同一会话、目标与 `request_id` 的重复调用直接返回原运行状态。去重只比较业务参数，不比较 `background` 等执行方式。
- 应用重启后重复调用可能再次审批，但批准后按持久任务身份命中已有任务，不重复收费提交。
- 父会话重开后仍能查询其拥有的子 Agent 运行，不重启执行、不重放通知；兄弟与外部会话不能借恢复过程越权。

## 8. 文件读取与复合操作的交界

外部文件批准绑定规范化路径、实际文件身份和读取方式。批准后重新核对父目录／符号链接目标，发现替换就拒绝。路径解析范围、文件类型限制、分页、图片限额及历史副本见 [文件读取合同](short-drama/agent-tools.md#run-files-read)。

FFmpeg 的每个显式输入都匹配 `files.read`，可将同次调用的输入合并展示；批准后使用冻结副本。审批不能代替 [FFmpeg 合同](short-drama/agent-tools.md#run-ffmpeg)中的参数和路径校验。

## 9. 实施与验证

### 实施顺序

1. 审批请求独立身份、子 Agent 运行的父会话查询、去重比较范围，三项行为先落地。
2. Run 改为命令定义表，所有命令显式声明能力或 none，未知命令拒绝。
3. 人物、物品生图迁入 `character`／`item` 分组并接入 `generation.image`，同步 help、技能、实际调用方和协议测试（description 与技能版本按第 3 节先确认）。
4. 以普通工具、Run、子 Agent、Codemode 的实际调用链验证无旁路，再做固定文件与模拟上游的完整授权／执行／恢复验收。

每步保持既有功能可用；不要求先开放 operation 级设置或 key。不新增 REST API、供应商账号或密钥，不新增 SQL 约束。

### 验证矩阵

| 范围 | 必须通过的行为 |
|---|---|
| 命令表 | 同一记录绑定操作和权限；未知／漏声明拒绝；授权与执行使用同一规范化输入；模型不能伪造 operation、权限或作用域 |
| Run 生成 | 普通配置 Write 零生成；拒绝／等待阶段零正文读取、零解码、零上传、零模型提交（允许素材库元数据探测）；允许后仅执行冻结请求；审批期间配置变化返回 conflict |
| 规则存储 | 四层优先级、无 episode、跨作品、同身份恢复及并发设置；保存／加载失败不放行；未注册动作不能继承无关许可 |
| 审批 | 同一工具调用两个操作同时等待，批准／取消互不影响；重复点击只执行一次；目标变化或最新 deny 阻止；规则保存失败可见且不误批准 |
| 去重 | 同 request_id 仅 background 不同时复用原运行；重启后重复调用不重复提交 |
| 父子会话 | 子 Agent 按发起会话规则授权；父会话重开后仍可查询子运行；兄弟和外部会话拒绝 |
| 文件与复合操作 | 批准前无外部文件正文读取；路径及符号链接替换拒绝；FFmpeg／导入不绕过 files.read |
| UI 与平台 | Windows／macOS／Android 分支的作用域选择、错误、恢复继承及切换会话；原生能力缺失与审批拒绝分别展示 |

Flutter 命令统一使用 FVM，测试串行并以明确退出码判定结束；生成源修改后运行项目 codegen 并审查差异。真实模型评测需另行开启，固定文件、模拟 adapter 和 Widget 平台分支不能替代真实模型或原生设备验收。失败时停止受影响入口并保留原请求、已提交任务、输出和权限规则；不重新收费提交，不用删除业务数据回退框架改动。
