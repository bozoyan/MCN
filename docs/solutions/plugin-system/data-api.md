# 业务数据 API 与回调

> 业务数据 API 在 M2 交付；Event 与 Hook 属于后续迭代。任务进度只在[实施任务](README.md#实施任务)维护。

## 业务数据 API

插件通过 Host API 读写应用业务数据。例如“人物整理”读取人物资料、整理内容，再调用人物更新接口。

```text
插件处理函数
  → Host API 身份与权限检查
  → 业务 Service / Orchestrator
  → 版本校验、事务、变更记录
  → 持久化
  → 宿主界面观察更新
```

- 首批覆盖章节与人物的读取和修改，接口挂在 `context` 上，输入输出为 JSON DTO，不暴露 Dart 对象。
- 不为插件提供绕过业务规则的任意 SQL 接口。数据修改复用现有业务入口，内置界面、Agent 工具和插件经过相同的校验。
- 写入接口要求传入读取时得到的版本；版本不一致时返回可诊断的冲突信息，不覆盖用户的新编辑。
- 删除遵循软删除规则。
- 每次调用检查插件是否持有对应权限，未授权返回 `permission_denied`，并在结果中给出缺少的权限名。
- 当前作品范围内的读取与跨作品批量读取使用不同的权限名。

T-20 中先完成（可与 M1 并行）：首批接口签名、权限名清单、各接口对应的现有 Service 入口和版本字段。完成后补入本节，并同步更新 [SDK 类型](architecture.md#插件上下文-api)。

调用 AI 的接口（`ai.invoke`）不在 M2 范围。AI 请求通常超过单次执行的 60 秒上限，需要独立的任务身份、取消和结果订阅，列入[后续迭代](README.md#后续迭代)。

## Event 与 Hook

后续迭代。以下是已确定的语义边界，接口在出现具体插件需求时设计。

| 回调 | 示例 | 语义 |
| --- | --- | --- |
| Event | `document.saved`、`character.updated` | 操作已经成功，通知订阅者；订阅处理失败不撤销业务提交 |
| Hook | `document.beforeSave` | 提交前调用，允许的返回结果由该节点规定 |

- 每个 Hook 必须明确调用顺序、可修改字段、允许或拒绝的结果、等待和超时策略、异常处理及取消行为，不对所有节点套用同一种失败后继续策略。
- Host 在 Service / Orchestrator 的明确业务节点调用回调，使内置界面、插件和其他调用方经过相同边界。只实现真实需求使用的节点。
- 事件只携带资源 ID、版本和必要元数据，读取正文仍经过权限检查。
- 插件写入后可能再次触发事件，事件须携带来源插件、操作 ID 和因果关系，Host 限制循环深度。前置 Hook 对当前操作的变更通过返回结果表达，避免递归调用同一保存操作。
- 回调与工具调用一样，每次派发新建运行时执行。
