# VC：图片节点的视角与构图（镜头、打光、720° 全景）

> 本文定义制作画布图片节点上「视角与构图」三项能力的功能合同与实施拆分。进度只在[实施任务](README.md#实施任务) VC-01 至 VC-06 维护。

[返回方案总览](README.md) · [片段与制作](production.md) · [导演台](director.md) · [功能验收](verification.md)

## 背景

作者在制作画布上已有角色图、场景图或首帧后，常需要“同一画面换个机位”“换个打光”“在同一场景里取多个机位”。目前只能改提示词重新生成，或进导演台摆白模，二者都不能直接以已有图片为底。

镜头和打光使用有限的离散档位，提示词在客户端由固定模板拼出，作为节点的可见提示词。3D 只用于示意或本地取景；生成结果总是新节点，原图不被覆盖。全景生成复用图生图，查看器与截图完全本地，截图不调用模型。

## 目标与成功信号

| 目标 | 成功信号 |
|---|---|
| V1 换机位 | 选中一张图片，在面板里选角度与景别后一次提交，画布出现新图片节点，输入边指向原图，人物与场景保持可辨认的一致性 |
| V2 换打光 | 同一入口选方位、亮度、质感、色温后生成新节点，原图与采用结果不变 |
| V3 场景全景 | 从场景图生成 2:1 全景图；在查看器中自由取景，当前视角或四向截图立即落为新的图片素材节点，不消耗生成额度 |
| V4 可审阅可重做 | 新节点的提示词为模板展开后的完整文字，作者可在节点里修改后按现有流程重做；任务、历史、采用、导出全部沿用图片节点合同 |

## 范围与非目标

包含：桌面制作画布（Windows / macOS）图片节点的「视角与构图」菜单；镜头、打光两个派生生成面板；720° 全景生成；任意图片节点的全景预览、构图参考线、当前视角截图与四向截图。

不包含：12 向截图、截图自动超分、全景内放置人物、从全景截图自动重新生成带人物的镜头、导演台与全景互通、Agent 专用工具、移动端入口（制作画布本身不在移动端，见[范围](README.md#范围与非目标)）。查看器和截图底层放在 `lib/shared`，不依赖桌面专有 API，后续移动端可直接复用。

## 用户流程

1. 作者选中带采用结果的图片生成节点，或图片素材节点。浮动工具栏（`ProductionNodeBar`）新增「视角与构图」下拉：镜头、打光、720° 全景图。没有可用图片时整组禁用，并说明原因。
2. 选「镜头」或「打光」后，在节点下方打开面板：左边是球面示意，右边是离散参数和可选的补充描述，底部是「重置参数」、自动选定的模型名（只展示）和生成按钮。模型规则见[数据与真源](#数据与真源)；想换模型就在生成出的新节点里改，再按现有流程重做。参数在当前面板会话内保存，关闭面板即丢弃，不入库。
3. 点生成后，由 Orchestrator 在同一内容库事务中完成以下三件事，然后按现有图片任务流程提交：
   - 新建 kind=image 的自由图片节点：放在源节点右侧空位，标题为「源标题 · 镜头 右侧 45° 近景」这类派生名；
   - 写入模板展开后的提示词；
   - 建立源节点到新节点的 `generation_input`（reference）边。

   节点进度、失败、重做、历史和采用都走图片节点的既有交互。
4. 选「720° 全景图」时不弹面板，直接以同样方式建立全景节点并提交：使用全景模板，比例固定 2:1，模型在支持 2:1 的模型中自动选择；没有任何可用模型支持 2:1 时菜单项禁用并说明原因。新节点创建时即处于全景预览状态，生成完成后直接显示为查看器。结果就是普通图片资产，不另做标记。
5. 任何有可用图片的图片节点（生成节点的采用结果或素材节点）都可以从工具栏点「全景预览」，把这个节点切换为**全景预览状态**。图片按等距柱状投影展示，不判断是否真是全景，也不检查比例；非 2:1 的图片会出现拉伸，由作者自行判断。
   - **状态持久**：预览状态和最后的视角随节点保存。关闭画布、切换剧集或重启应用后再打开，节点仍是预览状态，并停在上次的视角。只有点「退出全景预览」才回到普通图片显示，同时丢弃保存的视角。
   - **节点内交互**：预览状态的节点卡片内容区就是查看器。未选中时，拖动节点和普通节点一样移动它；选中后，在内容区拖动改为旋转视角，标题栏仍用于移动节点。画布滚轮始终用于画布缩放，不拿来调 FOV。选中且画布获得焦点时，键盘 W/S/A/D 上下左右摇，Q/E 推拉 FOV。
   - **工具栏**：预览状态下，节点工具栏换成全景专属的一组按钮：退出全景预览、当前视角截图、四向截图、重置视角、三分构图线、全屏预览、快捷键说明。三分线开关只在本次会话有效，不保存。
   - **全屏预览**：交互与节点内一致，额外支持滚轮推拉 FOV，右下角显示 `横 θ° · 纵 φ° · FOV f°`。全屏和节点共用同一份视角，关闭全屏后节点停在全屏里最后的视角。
6. 截图在本地按当前或预设视角离屏渲染为 PNG。保存后登记为图片资产，并通过 `addDerivedOutput` 在全景节点旁生成素材节点，标题为「全景截图 · 前方」等，`derived_output` 边连回全景节点。四向截图按 2×2 一次放置。截图节点可直接连给视频节点或图片节点作参考。

## 数据与真源

不新增表或列，不改 migration。

| 内容 | 位置与规则 |
|---|---|
| 派生生成节点 | 普通 ProductionClips kind=image 行 + CanvasNodes（ref_type=production_clip），由新增的 `canvas_service.addDerivedImage` 建立；sceneId/sortOrder 为空。provider/model 自动选择：用户的全局默认生图模型（`resolvedAiModelOptionForKindProvider(kind: image)`）；没有或不可用时取第一个可用生图模型。该 provider 底层的 `resolveSelectableModelOption` 已经实现这个顺序，直接复用，不另写一套。全景先过滤出能力支持 2:1 的模型，再按同样顺序选；一个都没有时禁止提交。不继承源节点的模型。ratio：镜头／打光在源为生成节点时继承其 ratio，源为素材节点时按图片宽高取所选模型支持的最近比例；全景固定 2:1。resolution 继承源节点，素材节点用 `createImage` 默认的 1K，均受模型能力校验 |
| 参考关系 | 源节点 → 新节点一条 `generation_input` 边，role=reference；源为生成节点时按现有规则解析其采用文件，源为素材节点时用 mediaPath。不新增边类型 |
| 提示词中的参考 | 模板里的「参考图」写成指向该输入边的 `<ref>` 标签，提交时按现有规则转成「图片1」；删除输入边后标签显示失效并阻止提交，与 @ 引用行为一致 |
| 面板参数 | 不持久化。提交时展开为提示词文字写入 ProductionClips.prompt，GenerationTasks.requestJson 保存的就是最终请求，满足“展示实际输入”。不保存 `{template, args}` 结构，避免出现第二份真源 |
| 全景判定 | 不判断图片是否为全景，也不在资产上存标记。生成全景只体现为提示词与 2:1 比例 |
| 预览状态 | 存在节点上：`CanvasNodes.style` 的 `panorama` 键，值为 `{yaw, pitch, fov}`。有这个键就是预览状态，删除它就是退出。复用已有 JSON 列（节点颜色也存在这一列），不改 schema，备份随节点自动包含。各节点独立，同一文件放在两个节点上可以一个预览、一个不预览。全景派生节点在 `addDerivedImage` 的同一次写入中带上默认视角 `{yaw: 0, pitch: 0, fov: 75}` |

预览状态放在节点上而不是资产上：它描述的是“这个节点怎么显示”，不是“这张图是什么”。放在资产上，会让引用同一文件的其他节点被动改变显示方式。

视角写入时机：进入或退出预览时立即写入；拖动、键盘或全屏操作结束后，防抖 500 ms 写入一次，不在每帧都写库。写入走制作画布 `canvas_service` 新增的 `setPanoramaView(nodeId, view?)`：它校验节点属于制作画布、类型为图片且未删除，然后只更新 `style` 中的 `panorama` 键，保留节点颜色等其他键。视角变化不进入画布撤销历史。

`style` 是每个节点各自一份的 JSON，与节点类型无关，现有数据直接兼容。读取方只认自己的键：颜色用 `canvasNodeColorValueOf`，没有 `panorama` 键即普通显示。所有写入必须在原 map 上合并，不能整份替换。现有的颜色修改（画布面板、Agent 画布工具）都经 `canvasStyleWithColor` 合并，不会冲掉 `panorama`；通用 `canvas_service.updateNode` 的 `style` 参数会整份替换，新增调用方必须先合并再传。复制节点不继承预览状态。

## 提示词模板

模板以 Dart 常量放在 `lib/shared/models/production/view_presets.dart`，同 `style_presets.dart` 一样只维护一份中文文本，不做 i18n。展开后的提示词在开头和结尾正常拼接本集风格，即沿用 `ProductionStylePrompt.assemble` 的 before/after，与普通图片节点一致。以下是首版文案草稿，最终文字以 VC-06 的真实模型评测结果为准，在本文中更新。

档位定义（界面文案走 i18n，提示词片段为固定中文）：

| 参数 | 档位 → 提示词片段 |
|---|---|
| 镜头·水平 | 0 正面；±45 左／右前侧 45°；±90 左／右侧面；±135 左／右后侧；180 背面。范围 −180～180，步长 45，左负右正，指相机绕主体的方位 |
| 镜头·垂直 | −60 低机位仰拍；−30 微仰；0 平视；30 微俯；60 高机位俯拍。范围 −60～60，步长 30，正值表示相机在上方。不提供 ±90，因为模型对正顶、正底视角的执行最不稳定 |
| 镜头·景别 | 大远景、远景、中景（默认）、近景、特写 |
| 打光·方位 | 左侧、右侧、顶部、底部、前方（默认）、后方（逆光） |
| 打光·亮度 | 柔和偏暗、适中（默认）、明亮、强烈 |
| 打光·质感 | 柔光（默认）、硬光 |
| 打光·色温 | 暖色、中性（默认）、冷色 |

模板草稿：

- 镜头：`以参考图为准，保持人物身份、外貌、服装、道具与场景布置不变，只改变拍摄机位：相机位于主体{水平}，{垂直}，景别为{景别}。保持原画面的光线与色调。{补充描述}`
- 打光：`以参考图为准，保持构图、人物、服装与场景完全不变，只重新布光：主光来自{方位}，亮度{亮度}，{质感}，{色温}光。{补充描述}`
- 全景：`以参考图中的场景为依据，生成同一空间的 360°×180° 等距柱状投影全景图，宽高比 2:1。水平方向左右边缘无缝衔接，地平线位于画面垂直正中，顶部与底部完整覆盖天花与地面。画面中不出现任何人物，保留场景结构、陈设、材质与光线。`

补充描述为空时，省略对应句。全景不提供补充描述输入；需要时作者可在生成后的节点里改提示词，再按现有流程重做。

## 全景查看器与截图

- **渲染方式**：使用 Flutter `FragmentProgram` 着色器 `shaders/equirect_view.frag`，在 pubspec 的 `flutter.shaders` 中注册。着色器把每个输出像素按 yaw／pitch／FOV／宽高比反投影成球面方向，再在等距柱状纹理上采样，水平方向环绕。该着色器在 Skia 与 Impeller 下均可用，覆盖 Windows、macOS，也能在 Android 上使用；不使用 flutter_scene，因为它只在桌面开启了 GPU，且全景不需要场景图。
- **交互状态**：yaw 无界（显示时取模到 −180～180），pitch 限定 −85～85，FOV 30～100（默认 75）。拖动灵敏度随 FOV 缩放。键盘 W/S/A/D 每次 5°，Q/E 每次 FOV ±5°。yaw／pitch／fov 是节点的持久状态，读写规则见[预览状态](#数据与真源)。拖动过程中查看器用本地状态（Hooks）即时渲染，操作结束后再防抖写库；数据库回读的值只在没有进行中的操作时同步进来，避免回读覆盖正在拖动的视角。
- **纹理加载**：查看器打开时解码采用文件，取 `ui.Image` 的原始尺寸；解码失败则在节点内显示错误，不显示空白视图。节点卸载或退出预览时 dispose 图像和着色器实例。
- **画布性能**：多个预览节点同时在画布上时，每个节点只在视角、尺寸或图片变化时重绘，不跑持续动画。节点内渲染的分辨率按节点在屏幕上的实际像素计算，不按原图尺寸。节点离开可视区域时，沿用画布已有的节点构建与回收行为，不为预览节点常驻纹理。同一文件的解码结果按路径共享，节点与全屏查看器不重复解码。
- **截图**：
  - 使用同一着色器在 `PictureRecorder` 中按输出尺寸绘制，经 `toImage` 编码 PNG，不截屏幕像素，因此不带构图线和 HUD。
  - 输出比例跟随本集制作默认比例，长边 1920。
  - 四向截图保持当前 pitch 与 FOV，yaw 分别取 0／90／180／270，命名为前方／右侧／后方／左侧。
  - 逐张渲染并写盘，写完一张、释放后再渲染下一张。中途失败时，已完成的截图保留并登记，失败原因按张显示。
- **画质提示**：2048 宽的全景在 75° FOV 下，有效源像素约 430 px，放大到 1920 会明显变软。生成全景时优先选模型支持的最高分辨率；查看器在有效源像素不足输出宽度的一半时，在 HUD 显示画质提示。不在本方案内自动超分。

## 服务与编排

| 文件 | 职责 |
|---|---|
| `lib/shared/models/production/view_presets.dart` | 档位枚举（遵循 enum-naming）、模板常量与 `expand(ViewPreset, args)` 纯函数 |
| `lib/shared/services/production/view_derive_orchestrator.dart` | 校验源节点有可用图片、模型能力（全景校验 2:1）后，调用 `canvas_service` 新增的 `addDerivedImage`，在一个 `write` 内依次完成 `shots.createImage`（values 带提示词、比例、分辨率、模型）、`ensureClipNode`（放在源节点右侧空位）与 reference 输入边写入。不复用 `addImage` 加 `saveImage`，因为这是两次独立写入，中途失败会留下空节点。写入成功后交给 `ProductionImageGenerateOrchestrator` 提交。提交失败时保留新节点与提示词，作者可以直接重试，不回滚节点 |
| `lib/shared/services/production/panorama_service.dart` | 登记截图资产、调用 `addDerivedOutput` 并按 2×2 放置 |
| `canvas_service.setPanoramaView` | 进入、更新、退出预览状态；只改 `style.panorama`，并做制作画布与节点类型校验 |
| 模型自动选择 | 在桌面面板侧读 `resolvedAiModelOptionForKindProvider(kind: image)` 和可用选项，全景先按 2:1 能力过滤，把选定的 provider/model 传给 Orchestrator。Orchestrator 不读 Riverpod，只校验传入模型的能力 |

## 验收

- 镜头／打光：生成后原节点的采用文件、提示词和输入均不变；新节点的提示词就是模板展开结果，可编辑后重做；删除新节点不影响源节点。
- 全景：自动选到支持 2:1 的模型，一个都没有时禁止提交；任意图片节点都能进入全景预览；重启应用后仍是预览状态且视角不变，退出后恢复普通显示；生成全景的新节点直接以预览状态出现；查看器拖动、缩放、键盘控制和重置正常；画布上同时有 5 个预览节点时平移、缩放画布不卡顿；关闭后 GPU 资源释放（反复开关 20 次，内存不持续增长）。
- 截图：不经过网络和生成任务；文件进入受控目录并登记资产；节点和 `derived_output` 边正确；备份恢复后截图节点可预览。
- 平台：Windows、macOS 各自实机运行一次查看器与截图。只在一个宿主上通过的测试不计作跨平台验收。Android 不在本方案验收范围。

## 风险

- 图生图模型对“只换机位”的执行不稳定，可能连带改变人物外貌。缓解办法是由 VC-06 评测定稿模板；把镜头作为“快速探索”入口，需要精确机位时仍用导演台。
- 全景两极与左右接缝的质量取决于模型。查看器把 pitch 限制在 ±85°，接缝问题在评测中记录，不在客户端做修补。
- 节点内旋转视角依赖手势竞技场：画布节点拖动由 vyuh_node_flow `ElementScope` 的 `RawGestureDetector` 平移识别器处理，节点内容区的平移识别器层级更深，按机制应先胜出。这一点未实际运行验证，VC-04 第一步先用 Widget 测试确认。若不成立，退路是节点内只显示当前视角、不响应拖动，旋转视角只在全屏预览中进行；预览状态和视角的持久化不受影响。
- 低分辨率全景截图偏软。缓解方式是生成时优先选高分辨率，并在 HUD 给出画质提示。
