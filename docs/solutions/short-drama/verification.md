# 短剧功能验收

本文定义短剧制作功能的检查项、执行入口和上线后的产品运营指标。功能验收结果记录在 [实施任务](README.md#实施任务)，写清平台、命令、结果及未验证项；运营数据单独用于判断使用情况与改进方向。测试文件存在不代表已经通过。

[返回方案总览](README.md) · [制作与画布](production.md) · [导演](director.md) · [剪辑](editing.md) · [Agent 工具合同](agent-tools.md)

## 验收范围

- 制作、导演、剪辑和本地编码在 Windows、macOS 分别验证。共享工具、数据、权限设置和审批同时检查 Android；Android 构建成功不代表桌面媒体能力已可用。
- 普通回归使用隔离数据库、固定媒体和模拟供应商响应，不调用付费模型。真实生成效果评测须由用户单独开启，并确定模型、样本和预算。
- 数据、工具协议和界面可分别验收。导出与播放还须在实际桌面运行环境验证，不能用模拟编码器或界面截图代替成片检查。
- 按改动范围选择最窄的测试，所有 Flutter 测试通过 FVM 串行执行。文档不要求每次修改都重跑完整制作流程。

## 固定样例

准备一个测试作品，含两名角色、两个场次和若干按场内顺序排列的视频片段。至少一段提示词包含多个镜头；另放一个不属于场次的试验节点，用于检查直接成片的选择范围。

媒体样例包含横屏与竖屏视频、有声与无声视频、一张图片、一段音频，以及缺失或损坏文件。剪辑样例覆盖叠层、字幕和跨 120 帧分块边界。导演样例包含人物移动与摄影机关键帧。文件和作品均使用测试数据。

## 功能检查

### 数据、工程与资产

| 检查项 | 通过条件 |
|---|---|
| 原有内容 | 制作操作不改动原剧本、角色、地点和场次顺序；旧图片身份、路径及业务引用在正式迁移后仍可读 |
| 剧集与剪辑 | 新建剧集在同一事务内创建并关联空 `VideoEditing`；历史有效剧集的空关联由 `episode_editings_v1` 初始化任务补齐，已有非空关联保持原样；重复执行不重复建工程，失败不记录任务完成 |
| 失效关联 | 打开剧集时，非空但失效的剪辑关联明确报错，不自动替换为新工程；工程名称、画幅和内容可独立于剧集编辑 |
| 导演身份 | 导演使用 `VideoStagings`，节点通过 `video_staging` 引用工程；保存、重开、历史恢复使用同一份文档，不另建平行草稿 |
| 媒体导入 | 图片、视频和音频导入后可读取、预览或试听；媒体规格与实际文件一致，缺失或损坏文件明确失败，不留下可用假象 |
| 备份恢复 | 作品、片段、画布、导演与剪辑工程及其引用媒体完整；已不再采用但仍被剪辑引用的素材保留；恢复不触发新生成，预览缓存可重建 |

### 片段、画布与参考输入

| 检查项 | 通过条件 |
|---|---|
| 片段与画布一致 | 手工和 Agent 编辑同一 `ProductionClips` 内容；创建片段与所需节点原子完成；移动画布节点不改变场次或成片顺序 |
| 引用与输入同步 | 提示词中的 `ref` 身份、输入用途和顺序一致；中文、引号及特殊字符可往返；引用缺失、自连、成环或跨画布输入在提交前被拒绝 |
| 原子保存 | 只改提示词周围文字时保留已有引用；变更引用时同时提供完整 `inputs`；失败不留下半份提示词或输入关系，取消编辑不写库 |
| 素材复用 | 选用文件或历史结果不发起生成；共享素材节点不会因另一目标改选输入而被改写；断开输入不删除源素材 |
| 采用与任务状态 | 当前采用文件与最新任务状态分别展示；生成失败保留旧采用；手工切换历史结果不新增任务，重复或迟到回调不覆盖后续选择 |
| 制作画布边界 | 每集只关联自己的制作画布，并发打开不重复创建；普通构思画布入口不混入制作画布；移除节点或画布后，既有任务和素材仍保留 |
| 人工与 Agent 协作 | 工具写入可审阅、回退；人工保存正确接管对应范围；保存失败保留编辑内容，切换或关闭时正确处理未保存输入 |

### 生成、取消与恢复

图像、视频和音频分别使用实际适配器对应的参数合同，音频专项见 [音频生成](audio-generation.md)，参考存储专项见 [用户自配 S3](object-storage.md)。

| 检查项 | 通过条件 |
|---|---|
| 模型输入 | 请求使用已保存的提示词、规格和输入快照；不兼容的数量、格式、时长或参考用途在提交前失败，切换模型不静默丢失素材 |
| 重复提交 | 同一逻辑请求复用 `request_id` 时不新增生成任务；同标识但输入不同返回冲突；用户明确重做才创建新请求 |
| 提交不确定 | 供应商可能已接受而响应丢失时，不自动重新生成；已有上游任务 ID 时只查询原任务 |
| 结果保存 | 文件下载、资产登记和内容库采用分别检查；任一阶段中断后能继续原任务，不通过重新调用模型修复本地保存失败 |
| 取消 | 等待授权、排队、提交和下载期间的取消符合各阶段语义；无法确认上游停止时如实返回，迟到结果不自动覆盖用户选择 |
| 重启恢复 | 有回执的任务恢复查询与下载，重复恢复不重复登记或采用；本地编码不伪装为可跨重启恢复的生成任务 |
| 参考存储 | 上传失败、链接过期、凭据错误和存储切换有明确结果；上传失败不提交生成，生成结果仍保存到本地 |

### 导演、剪辑与导出

| 检查项 | 通过条件 |
|---|---|
| 导演输出 | 固定取景与关键帧输出符合工程；5 秒、24 fps 样例输出 120 帧，无编辑辅助线；PNG 和 MP4 可读，取消或失败不损坏工程 |
| 编辑与保存 | 移动、裁切、分割、复制、锁定、音画联动和混音符合当前命令合同；越界、非法重叠或旧修订写入被拒绝，失败后工程不变 |
| 共享撤销 | 手工与 `Run editing` 使用同一剪辑会话；整组命令只形成一次修订和撤销记录，撤销不覆盖之后的人工修改 |
| 素材固定 | 剪辑引用明确的素材文件；重生成、切换采用结果和改变场序不改已保存时间线；缺失素材保留引用并阻止错误导出 |
| 预览与混音 | 119、120、121 帧边界无漏帧、重帧或累计音画漂移；跨块音频、淡入淡出及叠层正确，旧修订缓存不覆盖新工程 |
| 字幕 | `burn`、`srt`、`none` 按当前剪辑合同输出；字幕时间、文字和编码正确，导出选项不回写时间线内容 |
| 直接整集成片 | 只取场次内已采用的视频，按场序和场内顺序合成；独立试验节点不混入结果；画幅、帧率和音频统一，无声段正确处理，不读取剪辑工程 |
| 剪辑成片 | 输出使用指定的冻结工程修订；画面顺序、层级、裁切、混音和字幕与时间线一致；导出期间继续编辑不改变本次结果 |
| 文件交付 | 单段、批量和整集输出不覆盖已有文件；批量视频与 Markdown、CSV 提示词表逐段对应；取消、磁盘满、目录无权限和交付中断均保留原素材 |
| 原生媒体 | 安装包中的实际编码器可生成合同要求的 H.264、YUV420P、AAC 文件；用 FFprobe 和实际播放器检查规格、切点及音画同步，不能只检查文件是否存在 |

### Agent 工具

调用参数以 [Agent 工具合同](agent-tools.md)为准。

| 入口 | 必须检查的行为 |
|---|---|
| `Run providers list/read/models` | 配置变化实时可见且不泄露凭据；`models` 按 `kind` 一次返回全部配置模型的完整详情，含 `capabilities`、`defaults` 和可用状态；未知能力明确表示未知，不再提供单独的 `model` 子命令或 Read 资源入口 |
| 资源 Read、Write、Edit、Create | 身份与作用域正确，字段读取返回原值；不借资源读取访问普通文件，不通过旧剧集剪辑路径修改工程；参数错误不产生写入 |
| `Run production` | 使用已保存片段配置发起生成；检查请求复用、权限拒绝、任务查询、取消和结果应用，不绕过业务服务 |
| `Run editing` | 通过 `editing_id` 读取和编辑工程，沿用共享会话的版本、锁定、素材和撤销校验；Agent 操作后手工界面能看到相同结果 |
| `Run files read` | 普通文件读取经过授权；文本分页无丢字，图片返回可供模型读取的内容；历史消息使用会话副本，原文件删除后仍可重放；不接收 Android `content://` URI |
| `Run ffmpeg` | 只处理声明的本地输入和输出，文件权限、参数限制、取消及重复请求检查有效；生成图片能通过会话结果交给模型，不执行任意 shell 或网络读取 |
| 权限与后台操作 | 拒绝授权不执行实际动作，批准前后目标保持一致；主、子会话的运行身份正确，查询和取消不越权；切换会话不串通知，完成通知不重复，停止行为区分前台与后台任务 |

完整本地流程至少手工走一次：片段编辑 → 画布输入 → 导入并采用固定媒体 → 文件检查 → 剪辑 → 成片导出。再分别插入一次授权拒绝、保存失败、取消和重开，确认已有内容保留、后续动作可继续。生成提交与恢复使用模拟供应商测试，真实模型效果另按下节执行。

## 上线后的运营指标

运营指标关注作者是否用起来、能否完成制作，以及哪里最容易中断。先积累基线，再根据实际使用情况设目标，不预设完成率或失败率门槛。

| 指标 | 统计口径 | 用来判断什么 |
|---|---|---|
| 制作使用量 | 统计期内开始制作的集数，以及发生片段编辑、素材采用、剪辑或导出的集数；同一集重复打开不重复计数 | 有多少制作需求，哪些能力被实际使用 |
| 制作完成率 | 以同一批开始制作的集为分母，在统一观察期内成功导出成片的集为分子；直接成片与剪辑成片分别列出 | 作者能否从开始制作走到最终交付 |
| 流程中断位置 | 查看编辑片段、采用可用素材、剪辑、导出各步骤的到达情况，以及最后停留步骤；导入素材和直接成片都是有效路径，不要求每集经过生成和剪辑 | 哪一步值得进一步排查；停留本身不等于功能故障或作者放弃 |
| 生成成功率 | 按唯一生成任务统计成功、失败和取消；成功要求结果已保存并可用；运行中和提交不确定单列，查询、下载或登记重试不新增任务数 | 哪些渠道、模型或输入类型影响结果交付；接口成功不代表内容质量合格 |
| 导出成功率与耗时 | 按实际启动的导出统计成功、失败、取消及处理耗时；成功要求文件交付完成且可读；区分直接成片、剪辑成片、平台和成片时长 | 本地输出是否可靠，等待时间是否成为使用障碍 |

比较时固定版本、平台、观察期及适用的模型或输出类型，同时保留分子、分母和样本数。观察期未结束或样本不足时不急于下结论；重复导出同一集不增加制作完成集数。重做次数可作为排查线索，不能直接解释为用户不满意。

先核对现有数据能支持哪些口径，缺失的指标标记为暂不可统计，不把缺失数据记成零。这里只定义产品要观察什么，不要求为短剧功能验收扩建采集系统，也不把上报队列、投递延迟或后台报表建设列为功能通过条件。

## 真实模型效果评测

仅在用户明确要求后运行。开始前确定要回答的问题、具体渠道与模型、允许上传的素材、请求次数和费用上限，不预设固定供应商矩阵或付费请求数量。

- 检查片段生成时，核对场次归属、关键动作与对白、镜头顺序、时长和素材引用是否符合原文；记录具体遗漏和错误。
- 检查视频、音频生成时，核对文件规格以及人物、动作、声音是否符合提示词；接口成功或自动采用不能代替内容检查。
- 比较导演参考是否有帮助时，固定文字、角色和参数，只改变参考输入；保留各次结果、重做次数及实际费用，由作者判断是否更接近目标。
- 每次保留模型 ID、输入、请求参数、任务 ID、输出和失败原因。恢复下载不重提生成；结果只代表实际运行过的样本和模型。

不要求为功能验收新增评测平台或付费跑批脚本。没有执行真实模型时，明确记录“未验证生成效果”。

## 性能与生命周期

性能采样按实施任务中的授权范围执行。获准采样后，固定设备、构建模式、数据量和操作步骤，检查输入、拖拽、播放、导演开关和导出时的响应，并记录 CPU、内存、帧间隔及异常样例。

重点确认关闭页面后播放器、渲染任务和监听正常释放，重复打开不会持续累积资源；机器较慢时也不能丢失导出帧或生成损坏文件。性能门槛基于实际支持设备和用户需求确定，不把未经测量的数值写成发布条件。
