# C：内置多轨剪辑与成片导出

> 直接导出与内置多轨剪辑属于同一版本，先具备顺序合成能力再接编辑器。新增功能面向 Windows / macOS，共享逻辑保留 Android 接入能力。进度只在[实施任务](README.md#实施任务) C-01 至 C-05 维护。

[返回方案总览](README.md) · [直接导出与制作](production.md#导出)

## 目标与范围

作者可以在 Reveric 内将本集采用视频编排成多轨时间线，加入图片、配音和 BGM，预览后导出 MP4。剪辑工程独立保存，当前制片场景由每个 episode 引用一个工程，关闭应用后可继续编辑。X 可独立完成顺序成片，C 在它的媒体合成能力上增加编辑、工程保存和组合预览；直接导出、手工多轨编辑与 Agent 剪辑共同构成本方案的完整剪辑交付。

| 能力 | 功能合同 |
|---|---|
| 视频轨 | 多条视频／图片轨；上层覆盖下层，可调整位置、缩放和透明度；无画面区间输出黑底 |
| 音频轨 | 视频原声、导入配音与 BGM；片段音量、静音、音频淡入淡出；多轨混音输出，防止叠加削波 |
| 编辑操作 | 移动、跨同类型轨道移动、裁切首尾、播放头处分割、复制、移除；同轨禁止重叠，跨轨允许叠加 |
| 时间线 | 唯一主视频轨自动磁吸、其他轨自由摆放；缩放、播放头、边界吸附、轨道锁定、隐藏／静音；视频原声跟随同一片段的源区间 |
| 工程 | 自动保存、会话内撤销／重做、重开恢复最后成功保存的工程；保存失败保留内存修改并明确提示 |
| Agent 剪辑 | 在现有聊天助手中按自然语言创建初剪、编排片段、裁切、分割、调整叠层及混音；与手工编辑共用工程、命令、校验和撤销 |
| 预览 | 低清分段预渲染，修改后只使受影响区间失效；缓存就绪后播放，未就绪时显示准备状态 |
| 输出 | 剪辑页导出当前工程的 MP4；沿用 X 的画幅、720P／1080P、24 fps、H.264/YUV420P 与 AAC 规格 |

Agent 接入复用当前已实现的字幕编辑、烧录和 SRT 输出。时间线变速、视频转场库、调色界面、特效关键帧、外部剪辑软件工程格式、多个剪辑版本分支、导出任务存档不因本次工具接入而新增；Run ffmpeg 处理素材不等于这些效果已成为可编辑的时间线属性。音频生成 G 的范围仍独立确定，C 可使用导入音频完成全部混音功能，不依赖 G。

## 入口与素材关系

制片页提供「剪辑」入口，打开当前集的独立剪辑工作区，保留返回制片页的路径。工作区包含素材区、预览区、片段属性区和时间线；不将完整编辑器塞进导出弹窗，不复用导演台的人物动作／摄影机关键帧工程。现有「片段／画布」视图继续服务于规划和生成。

每次新建 episode 自动创建并绑定有效的空剪辑。已有 episode 在打开制片／剪辑工作区时，若 editing_id 为空，则创建并绑定空剪辑；该过程不读取旧剪辑字段。空工程提供「导入采用片段」：按场次及场内顺序冻结当前采用视频并添加到主轨，原声直接使用同一视频片段的源区间。缺失或无效来源列出问题，不静默跳过；有现存片段时不自动重复导入。也可显式从素材区添加媒体。图片初始持续 3 秒，可延长；视频和音频使用实际可用区间。

工程建立后保存固定受控文件路径及可选资产来源，不持续跟随 `selectedFilePath`，不保存用于复查文件变化的 SHA。重新生成、更换采用结果、调整场次或片段顺序都不改写已保存的剪辑。替换素材由用户明确发起并校验源区间，替换时按现有 replace 命令重置源入点，持续时间取原长度与新素材可用长度中的较小值，并返回实际调整；图片保持原片段长度。素材缺失时保留引用并定位问题，阻止受影响区间预览和整片导出，不自动重生成。

从时间线移除片段只改变工程文档，支持撤销，不删除原素材、生成任务或制作片段。视频原声直接从源视频混音，跟随视频片段的裁切、分割、音量与淡入淡出，不建立 linkGroupId 或隐式音频副本。视频轨隐藏沿现有渲染逻辑同时跳过该轨的画面和原声；独立音频轨使用 muted 控制。需要独立音频时，经 Run ffmpeg 提取新文件后显式加入音频轨。

X 的「整集成片」始终读取当前采用片段；剪辑页的「导出」始终读取当前剪辑工程。两个入口不互相覆盖数据或隐式切换导出来源。

## 工程模型与保存

目标结构在作品内容库新增独立 `VideoEditings` 表，SQL 表名 `video_editings`，记录类型 `VideoEditingRow`。工程拥有自己的 ID、名称、文档和修订，不在表内保存 episode_id 或 screenplay_id；作品归属由所在内容库确定。

| 列 | 类型与默认值 | 含义 |
|---|---|---|
| id | TEXT，非空，主键 | 独立剪辑 ID，新建时分配 |
| title | TEXT，非空 | 工程名称，不依赖 episode 标题持续派生 |
| document | TEXT，非空 | 通过 EditingDocumentConverter 保存 EditingDocument，创建时即为有效文档 |
| revision | INTEGER，非空，默认 0 | 并发保存修订，内容或名称修改时比较并递增 |
| created_at | INTEGER，非空 | Drift DateTimeColumn，沿用项目 Unix 秒时间戳写法 |
| updated_at | INTEGER，非空 | 创建、修改及软删除时更新 |
| deleted_at | INTEGER，非空，默认 0 | 沿用项目软删除约定 |

`document` 保存画幅、固定帧率、轨道、片段、字幕与素材路径，不保存素材内容校验值。ID、title 和 revision 只保存在表列中，不重复写进 JSON。继续整体校验和保存文档，不拆轨道表、片段表或剪辑历史版本表。

### 制片关联与生命周期

ScreenplayEpisodes 新增可空 `editingId` 列，SQL 列名 `editing_id`，单向引用 VideoEditings.id。当前每个 episode 对应一个工程；新建集时即创建并绑定有效空文档，列可空仅用于已有集尚未打开的状态。工程本身可独立存在，不要求绑定 episode。

```text
作品内容库
  VideoEditings：id / title / document / revision
       ↑
  ScreenplayEpisodes.editing_id
```

所有新建 episode 的业务入口，包括人工界面、Agent Create 和示例／导入流程，都调用同一创建编排，在同一内容库事务内创建 episode、有效空剪辑并写 editing_id，任一步失败整次回滚。空文档使用已有默认轨道、24 fps、当前剧本画幅；名称复制集标题，标题为空时用集编号。

打开已有集时调用同一 ensure 逻辑：事务内读取活动 episode，editing_id 为空则创建并绑定空工程；非空则校验并返回原工程。并发打开只返回同一个 ID，不能留下重复记录；非空引用已失效时明确报错，不把它当作“尚未初始化”。补建不读旧 editing_document／editing_revision，不导入旧时间线，也不自动填充现有采用视频。

Agent 无界面打开已有集时，使用单例资源 `Create /episodes/{episode_id}/editing`，复用上述 ensure；Write 同一路径等价，Read 仅返回关联或未初始化，不写库。新建 episode 的 Create 结果直接带 editing_id。制作业务负责这一关联，Run editing 仍只按 editing_id 访问独立工程。导入采用视频是独立、可撤销的编辑命令，不与空工程初始化混合；直接整集成片使用临时顺序文档，不额外建立工程记录。

新建时可从剧本复制画幅初值，之后由 EditingDocument 自己持有；剧本比例改变不自动修改已有剪辑。独立创建由调用方指定画幅。工程名称也独立编辑，不能因剧集重命名而隐式覆盖。

工程删除采用软删除，不删除媒体、生成记录或 episode。episode 删除不级联删除剪辑；无效或已删除的 editing_id 引用明确报错，不自动新建替代工程。新结构的备份收集工程记录及全部固定素材，包括仍需保留的软删除工程引用，不仅扫描已关联的 episode。

建立普通索引 `video_editings_by_deleted_at_updated_at` 与 `screenplay_episodes_by_editing_id`，分别支持工程列表和引用查询；当前每集一个工程由单个引用列及 Dart 业务校验表达，不添加外键、级联、CHECK 或表级 UNIQUE。

### 无历史兼容

当前实现仍使用 ScreenplayEpisodes.editingDocument／editingRevision；它们只作为本次重构的移除对象。目标 schema 移除这两列，业务读写、备份扫描、页面入口及测试全部切换到 VideoEditings 和 editing_id。不复制旧剪辑文档，不双读、不 fallback、不保留旧字段或 Run editing 的 project_id／episode_id 寻址别名。旧集打开时仅补建新的空剪辑，旧剪辑内容不恢复；不删除原媒体、片段或生成任务。

只支持新实体及新引用的备份恢复；旧内嵌剪辑不会被恢复成新工程。不提供旧版本应用回读新结构的能力。不兼容历史业务数据不等于省略数据库结构变更流程：建表、移除列和索引仍按实际发布基线实施，不为本地旧库添加运行时补列或兼容层。

### 文档与保存

文档 `format=reveric.editing`、`version=1`，包含固定 24 fps、输出画幅、轨道和片段。轨道记录 ID、媒体类型、顺序、锁定、隐藏／静音状态；片段记录 ID、轨道 ID、受控文件引用与可选素材 ID、源入点、时间线起点、持续帧数、关联组，以及对应的画面变换或音量／淡入淡出参数。源入点使用整数微秒；时间线位置和长度使用整数帧，区间统一为左闭右开，避免累计浮点秒数造成偏移。源时长按实际探测值换算为完整帧，可用区间不足一帧时拒绝添加。

每次编辑先执行 Dart 校验，确认非负位置、正持续帧数、源区间可读、同轨无重叠、主轨从第 0 帧连续排列和参数范围合法，再提交一个可撤销命令。一次拖动在释放时形成一条命令，拖动中只更新局部显示。移除片段或轨道是文档修改，不执行资产删除。

编辑提交后串行自动保存，按 `editing_id` 和已读取的 `revision` 比较并递增，拒绝旧修订覆盖新修订；文档与修订在同一条 VideoEditings 记录上原子写入。并发冲突保留本地修改并提示重新载入，不自动混合两个版本。切集、关闭编辑器或退出应用前等待待保存操作；保存失败允许重试或由用户明确放弃。撤销／重做也走相同保存路径，重开恢复工程内容，不承诺恢复整段会话的撤销栈。

新表、episode 引用列及旧列移除遵循发布记录与标签核验、Drift 结构变更和 codegen 规则；schema 版本按真实发布基线核定，不沿用旧方案的版本数字。结构升级不搬迁旧剪辑业务数据，测试核对新表的 Typed DAO 往返、引用和其余业务数据保留。

作品备份必须收集工程中全部素材及受控文件，包括已不再是当前采用结果的旧素材。恢复保留引用身份、时间线和修订，不触发生成；缩略图、波形和预览缓存可重建，不纳入业务备份。工程格式版本不支持时保留原文档并明确报错，不保存为空工程。

### 文档字段与编辑规则

| 对象 | 字段、单位与默认值 |
|---|---|
| 根对象 | format=`reveric.editing`，version=1，fps=24，ratio 创建时明确指定，制片入口可复制 Screenplays.ratio，之后不自动跟随；tracks、clips 为数组，revision 只用 VideoEditings.revision，不在 JSON 重复保存 |
| 轨道 | id、kind=video/audio/text、role、order、name、locked、hidden、muted；同类型 order 从 0 连续递增；只有一条 role=main 的磁吸视频主轨，主轨不能移位或删除；role 按 EditingRole 校验 |
| 文件引用 | filePath 为受控相对路径，mediaType 为 video/image/audio；assetId 可空且仅用于来源定位，不作为可读性前提；不保存 sha256 |
| 片段 | id、trackId、source、name、sourceInUs=0、startFrame、durationFrames；所有整数非负，durationFrames 大于 0，ID 在工程内唯一；文字 source 为空，其余 source 为冻结媒体引用；没有 linkGroupId |
| 画面片段 | scale=1，范围 0.2 至 1；opacity=1，范围 0 至 1；按现有 renderer 的等比缩放及定位规则渲染，不提供模型中不存在的 x／y 字段 |
| 声音参数 | 视频原声和独立音频均用片段 gainDb=0，范围 -60 至 +12；fadeInFrames=0、fadeOutFrames=0，非负且和不超过 durationFrames；独立音频轨可 muted，片段没有 muted 字段 |
| 文字片段 | 复用已有 text、textStyle（subtitle／title）、textPosition（top／center／bottom）及帧区间；导出按现有 renderer 选择烧录、SRT 或不输出字幕 |

视频片段的 source.hasAudio 决定是否从原文件混入原声；裁切、移动、分割直接改变这一片段的统一源区间，不生成第二条音频片段。独立音频轨仅接 audio 素材。图片不使用源时长裁切，sourceInUs 固定 0，持续时间由 durationFrames 决定。

主轨自动磁吸：从第 0 帧起首尾相接；拖动改变顺序，插入会推后后续片段，删除会向前补齐，裁切改变时长后重新排布后续片段。主轨不接受任意 startFrame 或自由跨轨 move，不能留下间隙。非主轨自由摆放，可移至同媒体类型的非主轨；移动／裁切产生重叠时拒绝。place 的落点已被占用时拒绝，否则新片段时长按现有命令缩短至下一片段起点，实际长度必须返回，不静默冒充请求长度。

拖动和裁切按帧对齐，边界吸附阈值为 8 个逻辑像素；Alt 仅关闭指针边界吸附，不关闭主轨磁吸。复制生成新片段 ID，主轨按插入位置重排，非主轨沿用 place 规则。分割点严格位于片段内部，右半段 sourceInUs 按分割帧换算递增。所有操作复用 EditingCommands 和 EditingDocument.validate，不创建平行的自由主轨或音画关联组模型。

手工替换文件先探测并校验源区间；更新路径与媒体规格是一次可撤销命令。打开、预览或导出时检查文件可读性、媒体可解码性及所需源区间，满足条件就使用当前文件，不因内容与加入工程时不同而拒绝。不计算或比较用于素材变化判定的 SHA。未知文档版本保留原始值并禁止覆盖；专用 converter 负责序列化，业务服务不手动重复编解码。

## Agent 剪辑

作者在剪辑工作区的现有聊天助手中提出操作，例如“把选中片段开头裁掉 1 秒，配音跟随裁切，再把 BGM 降到 -8 dB”。Agent 读取当前工程与选区，将要求转换为已有编辑命令，成功后时间线立即更新并保存，受影响预览失效；聊天显示改动对象和范围，作者可通过剪辑撤销或既有改动记录回退，不增加独立 AI 草稿工程或重复的接受步骤。

### 操作范围与上下文

- 从本集采用视频创建初始工程；读取当前时间线，添加/复制/移动/裁切/分割/移除片段，调整缩放、透明度、音量、轨道静音和淡入淡出。轨道顺序、主轨磁吸和视频原声区间遵循手工编辑的同一规则；锁定轨不能被 Agent 绕过。
- 上下文包含当前作品、editing_id、revision，以及已验证的制片 episode 关联、24 fps、播放头、选区、轨道/片段 ID、媒体类型、时长及可用源区间。大工程按轨道或区间读取，不把整个文件、缩略图或全部工程反复塞入常驻 prompt。
- 可加入工程已有文件、本集采用结果及用户任务范围内允许使用的素材，保存受控文件引用。素材目录通过 `/assets` 读取，文件内容通过 Run files 授权访问；外部文件进入长期工程引用前复用现有导入能力，不能持久化临时授权 URI。
- 按剧本、已授权读取的画面证据和明确时间要求编排；视频抽帧保留时间码。文字或音频元数据不能当作已观看／已试听的证据，缺少口型、对白或听感依据时说明限制，不隐式新增语音转写或节拍分析服务。
- 移除只修改工程中的片段或轨道，不删除媒体、生成记录或制作片段，不改变当前采用结果。编辑命令不隐式调用生成或 S3；Agent 可另行按权限创建生成任务，或显式调用 Run editing export。

### Run editing 工具合同

工具方案确定为 Run editing，详见 [Agent 接入合同](agent.md#剪辑工程)。list／create 在当前作品上下文列出或创建独立工程；read／apply／undo／redo／preview／export 使用 editing_id 寻址。apply 使用命令数组和 expected_revision，整组校验、一次保存、一次撤销。新建 episode 自动绑定空剪辑，已有集打开或单例资源 Create 时补建；导入采用视频作为独立编辑，Run editing 不把 episode 当作工程身份。export 冻结指定工程修订，直接导出由制作画布的 Write output 处理。

共享编辑会话承接当前桌面 EditingSession 的文档、串行保存和撤销职责，Agent 与人工界面共用。不能覆盖未提交输入或保存失败的内存修改，不能绕过锁定、源区间、重叠与修订检查。成功返回新修订及改动范围；整组失败保持原工程，取消不回滚此前成功写入，撤销不能覆盖后续人工修改。

Run ffmpeg 单独提供兼容参数数组的素材处理，输出新文件并可显式加入工程，复用现有编码队列和取消。Run files 单独负责授权后的文件内容读取，不扩展 Read 的文件语义。具体合同与权限、任务结果见 [Agent 全流程](agent.md)。

逐操作参数、结果、background、取消和描述草案见 [工具实施合同](agent-tools.md)。工具 description、参数 description 的具体文案在代码修改前单独确认。本轮只更新方案，不修改工具、提示词或打包技能；真实 Agent 效果评测仍须另行显式开启。

## 共用合成与预览

```text
当前采用片段 → X 临时顺序时间线 ─┐
                               ├→ 合成计划 → FFmpeg → 校验 → 保存 MP4
C 剪辑工程 → 冻结修订与素材引用 ─┘
                    └→ 按区间生成低清缓存 → 单播放器预览
```

共享合成计划负责源区间裁切、时间戳归零、帧率和尺寸规范化、补边、叠层、音轨定位与混音。X 只需要一条顺序画面轨及对应原声；C 使用完整轨道数据。直接导出无需先保存剪辑工程，两者均复用已有 `FfmpegRunner`、媒体探测和取消能力，不调用生成模型或外部服务。

本方案采用软件 H.264 编码，按统一规则规范化输入后合成；不把任意同编码文件的无损直拼列为必需能力。仅匹配分辨率和编码名称不足以证明码流可直接连接。具体编码器、原生包和许可证以实施时的锁定依赖与原生包能力为准，不能把旧选型当作当前构建事实。

### 音画规范化与混音

共享计划固定 24 fps、音频 48000 Hz 双声道，因此每帧正好对应 2000 个音频样本。视频边界按 `floor(durationUs × 24 / 1000000)` 取完整帧，不足一帧拒绝；源帧率通过 fps 滤镜规范化，旋转元数据在缩放前处理。画幅尺寸复用 ProductionSettings 的正偶数算法。空白输出黑底和静音，音频不足片段长度时补静音，超过时截到目标样本数。

音频按片段源入点裁切，归零时间戳，再按 startFrame 延迟；gainDb 转为线性增益，淡入淡出使用线性振幅曲线，以完整片段时间计算，不能在预览分段处重新起算。混音使用浮点 PCM 累加，关闭 amix 的自动归一化，防止轨道结束后其他轨道音量突变；浮点块先不限制峰值；全部 PCM 按顺序组装后，统一执行 alimiter（limit=0.95、attack=5 ms、release=50 ms、关闭自动增益、启用 latency 补偿），再编码 AAC，避免每个块重新起算限幅器状态。限幅会改变过大峰值的动态，不能替代用户调音。

### 分段缓存与连续播放

1. 缓存按 120 帧（5 秒）分块，预览短边 480，24 fps；最后一块使用实际剩余帧数。每块分别保存无声 H.264/YUV420P 视频和 48000 Hz 双声道浮点 PCM 音频，避免独立 AAC 编码产生边界 padding。
2. 视频块使用一致的编码参数和 time base，每块以关键帧开始、闭合 GOP、禁用 B 帧、不引用前后块；音频块长度严格等于该块帧数 × 2000 个样本。片段位置、淡入淡出和混音都按整条时间线的绝对位置计算。
3. 缓存键包含文档格式/渲染算法版本、区间、画幅和规格，以及相交片段当前素材的内容指纹、裁切、变换、层级和音量参数。内容指纹仅在渲染缓存层用于判断是否复用已编码片段，不写入工程作为校验值，不与加入工程时的旧值比较，也不阻止使用变化后的素材；内容变化时重新渲染。重命名、选择态和轨道锁定不触发重渲染。移动或修改片段使旧区间与新区间失效；全局画幅修改使所有画面块失效。
4. 点击播放时冻结工程修订，等待需要的块就绪后组装一个 `preview.mp4`：视频 concat demuxer 合并并复制码流，PCM 块按样本顺序流式拼接，整条音轨统一限幅并只编码一次 AAC，再与视频封装。播放器打开这个连续文件，按原播放头定位，不能用计时器逐个切换块文件假装连续播放。
5. 工程修改后暂停组合预览并标记失效；新缓存完成前不播放旧修订。只重编码变化的画面/PCM 块，但完整预览文件需要重新封装且音频需要重新编码，耗时和临时空间属于明确代价。开始播放前必须等待当前修订的连续文件就绪，不承诺边编辑边实时合成。
6. 组装结果用修订号和操作 ID 复查；旧任务异步结束不得覆盖新 preview.mp4。组装失败保留工程及有效块缓存，显示具体阶段，可重试；退出编辑器取消当前预览任务并释放单播放器拥有权。

concat 只用于应用按统一参数编码的缓存块，不直接连接任意用户文件；FFprobe 复查每块 codec、time base、规格和帧数，全部一致才允许码流复制。这遵循 [FFmpeg concat 的输入约束](https://www.ffmpeg.org/ffmpeg-all.html#concat)。不同来源先经共享合成计划规范化。

### 调度与资源界限

只允许一个 FFmpeg 编码会话，导出优先：先取消并等待后台预览停止，再启动导出；导出结束后按最新修订恢复预览需求。任务间共享取消与资源释放机制，不分别创建失控的编码队列。

预览缓存默认上限 2 GiB，按最近使用淘汰未被当前操作占用的块；已淘汰块需要时重建，不改变用户工程。组装中的文件与导出临时文件单独按可用空间预检，不计作可任意删除的历史缓存；空间不足报错，不删除素材或已有输出。大工程超出缓存容量时逐块生成并写入本次组装暂存区，完成后释放暂存，保留的可复用缓存仍不超过上限。

每次只处理当前 5 秒区间的素材，视频叠层逐层合成，最多同时解码一条素材视频和一个中间画面；音轨逐条累加到浮点中间结果，组装成完整连续音轨后统一限幅。内存不随整集总时长线性增长；仍可能有显著磁盘开销和等待时间。抽帧、缩略图与波形任务使用同一调度入口，首轮不同时拉起多份 FFmpeg 会话。

## 成片任务与失败处理

导出先等待工程保存，再冻结当前修订、素材引用、总帧数和输出规格；运行中编辑不改变已启动任务。总时长取最后一个有效片段的结束帧，音频长于画面时尾部输出黑底；全空工程不可导出。视频轨被隐藏、音频被静音时仍保留片段的时间范围。

在应用临时目录编码，按阶段和 FFmpeg 已处理时长报告真实进度；验证目标尺寸、24 fps、视频帧数、H.264/YUV420P、AAC 及可解码性，视频长度误差不超过一帧，音频尾部允许编码器 padding，但不得累计漂移。最终导出复用同一分块和样本规则，在目标分辨率生成中间视频/PCM，最终音轨只编码一次 AAC。确认输出完整后由人工保存面板或 Agent 指定的合法目标交付，不能先把半成品写成最终成片。

取消、损坏输入、磁盘满、编码失败和保存失败分别报告。清理范围只限本次创建的临时文件，不动原资产或用户已有目标文件；保存失败保留本次结果供当前操作重试，结束操作时清理。退出或崩溃后从已保存工程重新导出，不新增导出任务表、断点任务文件或自动重生成。
