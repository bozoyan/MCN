# 作品集合与可扩展过滤条件

本文定义小说、剧本书库的统一集合导航，以及集合包含条件的数据结构和执行方式。实施基线为 `225cbc16`（`feat: novel/screenplay collection v1`）；本文是实施方案，不代表功能已经落地。

## 1. 背景与目标

当前集合通过 `NovelCollections` 和 `NovelCollectionMembers` 保存名称、作品类型与手动成员关系，支持一部作品属于多个集合。桌面和移动端已经接入；集合按创建时间排列，进入集合后再按状态、分类等条件筛选。

首页同时存在集合封面区与“全部 / 创作中 / 已完本”状态入口。两者都用于缩小作品范围，却采用不同的导航层级。本方案统一入口，并允许用户保存自动收录作品的条件。

本次默认集合范围以用户提供的界面为依据：截图显示全部 12、创作中 9、已完本 3。`AllWorksHeader` 根据当前范围的状态计数动态生成标签，只展示有作品的状态；枚举中的所有可用状态不等于当前可见 tab。现有中文文案为“已完本”和“已放弃”，不另造名称。默认仅初始化全部、创作中、已完本；已归档、已放弃仅作为规则条件可选值，不预建集合。

目标：

1. 内置集合和用户集合使用同一层导航，保留新建集合能力。
2. 支持调整集合导航顺序，重启后保留。
3. 手动集合继续使用现有成员关系；规则集合根据条件动态收录。
4. 增加可筛选字段或操作符时，不改变集合外层结构。
5. 条件预览、列表和计数采用相同语义；未知条件不会被悄悄忽略。
6. 小说与剧本、桌面与移动端保持相同的业务规则。
7. 保留 UI 的过滤与作品排序，只支持网格展示，移除表格 / 列表模式及切换入口。

本次不做按集合保存的作品排序配置，不新增或持久化 `sortField`、`sortDirection`。UI 的过滤和作品排序控件继续保留，作用于当前集合的网格结果；取消表格 / 列表展示模式不影响这些能力。不做集合嵌套、引用其他集合、自动收录后的手动排除、模式转换、任意脚本、自定义 SQL、日期与相对时间条件。

## 2. 核心决策

采用版本化条件树、字段目录和查询编译器。持久化字段为 `builtin`、`filter_mode` 和 `filter`；Dart 属性分别为 `builtin`、`filterMode` 和 `filter`。只有全部集合标记为 builtin，所有默认集合通过应用初始化写入数据库。

沿用 `lib/shared/conditions/condition_evaluator.dart` 的 `all`、`any`、`not`、`compare` 表达格式。集合增加自己的强类型模型、严格校验与 SQL 编译，不改变通用条件求值器的现有契约。

不采用为每个条件单独增加集合列的方案，因为分类、标签和条件组合会持续扩展。也不将每个条件节点拆成数据库记录：规则以集合为单位编辑和保存，第一版没有单独查询规则节点的需求。

关键前提是第一版可筛选数据均来自应用数据库中的作品记录，不需要打开每部作品的内容数据库。未来加入章节、人物等条件时，必须单独评估跨库查询和更新通知成本，不能直接把昂贵计算挂进字段解析器。

## 3. 集合模型

### 3.1 统一持久化

所有集合都保存到 `NovelCollections`，包括初始化创建的默认集合。新增三列，现有身份、名称、类型、时间戳和软删除字段保持原样。

| 列 | 类型与默认值 | 语义 |
| --- | --- | --- |
| `builtin` | BOOLEAN，非空，默认 false | 系统保护标记；当前每种作品类型只有全部集合为 true |
| `filter_mode` | TEXT，非空，默认 `manual` | `manual` 手动成员；`rule` 条件匹配 |
| `filter` | TEXT，可空，默认 NULL | 带版本的条件文档，由专用 TypeConverter 转换 |

`builtin` 与是否由初始化创建是两个概念。创作中、已完本由初始化创建，但 `builtin=false`，之后与用户自建的规则集合一样可以改名、修改条件和软删除。

Dart 侧校验以下组合，不增加 CHECK、外键、触发器或表级约束：

- `builtin=true` 当前只用于全部集合，固定 `filter_mode=rule`、`filter=NULL`，查询当前作品类型的完整基础范围；每种作品类型只能有一条有效的全部记录。
- `builtin=false` 且 `filter_mode=manual` 必须对应空 `filter`，作品来自有效成员关系。
- `builtin=false` 且 `filter_mode=rule` 必须对应有效且非空的 `filter`，作品来自条件查询。
- 全部集合的 NULL 规则是明确的受保护组合，不能让普通规则集合缺失条件时退回全部。
- 未识别的模式标记为不支持，不能当成手动集合或全部作品。
- 普通创建与编辑接口不能设置或修改 `builtin`，仅初始化写入受保护记录；DAO 在事务内校验每种作品类型的唯一有效全部记录。
- 创建时选择模式，第一版不允许把已有集合切换模式，以免隐式转换或丢弃成员关系。
- 编辑规则必须校验成功后整体保存，不能部分更新条件树。

规则集合不写入 `NovelCollectionMembers`。其“加入 / 移出当前集合”操作不可用，仍可把其中作品加入其他手动集合。手动成员 DAO 也必须校验模式，不能只依赖界面隐藏按钮。

所有删除入口必须由 DAO 检查 `builtin`：为 true 时拒绝删除，UI 同步不提供删除动作。全部集合保持名称、模式与条件固定；其余集合使用现有软删除语义，不删除作品或修改作品状态。手动集合继续软删除成员关系，规则集合没有需要删除的动态成员快照。不再维护单独的内置删除偏好。

### 3.2 默认集合与初始化

新增 `lib/shared/services/initialization/collection_seeds.dart`，提供 `seedDefaultCollections(AppDatabase database)`。在 `lib/shared/services/app_initialization.dart` 的 `defaultAppInitializationTasks()` 注册一次性任务 `default_collections_v1`，复用 `ensureAppInitializationTasks` 的串行执行、完成记录和失败上报。

数据库完成 schema 升级后，既有应用启动初始化流程运行此任务。无需在 Widget、Provider 或每次打开书库时补建集合。现有 `AppStartupGate` 记录初始化失败后仍会挂载应用，不能假设失败会阻断启动：集合任务失败不写完成标记，下次启动会重试；若当前类型缺少有效的全部记录，书库显示集合初始化失败状态并提示重新启动重试，不展示伪造的全部集合，也不绕过初始化直接补写。若种子已提交、仅完成标记写入失败，则已有有效记录仍可正常使用。

为 `novel` 和 `screenplay` 分别创建以下三条记录，共六条。固定 ID 格式为 `collection:<content_kind>:<seed_key>`，比如 `collection:novel:all`。固定 ID 只用于种子去重和确定默认顺序，删除权限由 `builtin` 判断，不能依赖名称或 ID 前缀。

| seed_key | 初始名称 | builtin | filter_mode | filter |
| --- | --- | --- | --- | --- |
| `all` | 全部 | true | `rule` | NULL，仅基础范围 |
| `in_progress` | 创作中 | false | `rule` | `novel.status` 等于 `in_progress` |
| `finished` | 已完本 | false | `rule` | `novel.status` 等于 `finished` |

两个状态集合保存正常的版本化条件文档，根节点为单个 `compare`，不是运行时根据 ID 临时生成条件。全部名称按当前界面语言展示；普通默认集合初始化时写入本地化名称，之后按用户数据展示，不因语言切换或重新初始化覆盖改名。名称解析在初始化边界使用已加载的本地化资源，条件结构不受界面语言影响。

初始化步骤：

1. 在单个数据库事务中读取这六个固定 ID 对应的记录，查询必须包含软删除记录。
2. 只插入完全不存在的记录，写入 `builtin`、作品类型、初始名称、模式、条件及既有时间戳。旧的同名用户集合 ID 不同，不能用名称去重、覆盖或合并。
3. 已存在的记录保持原样，包括名称、条件、时间戳和 `deleted_at`；已软删除的普通默认集合不恢复。
4. 校验两种作品类型均有有效的全部记录，且受保护组合满足第 3.1 节约束；发现数据损坏时报告失败，不静默重写记录。
5. 提交事务后，由既有执行器在 `app_states` 写入 `app_initialization.default_collections_v1` 完成时间。

现有执行器先运行任务、再写完成记录，这两步不是同一事务。固定 ID 与包含软删除记录的存在性检查保证：种子已提交、完成标记尚未写入时崩溃，下一次重试也不会重复创建、覆盖修改或恢复已删除集合。事务内任一插入失败则全部回滚，任务不记完成，下次重试。

完成标记存在时跳过任务。以后需要新增默认集合，使用只包含新增 ID 的独立版本任务，不修改 v1 名单并重新运行来刷新默认值。当前方案未实现过虚拟集合版本，不新增针对旧提案偏好键的兼容迁移。

### 3.3 集合导航顺序

所有入口来自有效集合记录。排序仍作为页面偏好保存在现有 `app_settings`，不与成员关系或规则混存，也不在集合表重复保存一份顺序。

- 设置键：`library.collection_order.novel`、`library.collection_order.screenplay`。
- 值：按顺序排列的实际集合 ID 数组，包含种子 ID 与用户集合 UUID。
- 当前类型中 `builtin=true` 的全部集合固定第一，其余集合可以移动。
- 无保存顺序时，初始化记录按全部、创作中、已完本、已有用户集合排列；已有用户集合按 `created_at`、`id` 保持原相对顺序。种子记录缺失或软删除时直接跳过，不在导航层创建记录。
- 有已保存顺序时，保留仍有效 ID 的相对次序，去重并过滤已软删除或缺失的记录，新增集合追加到最后；全部入口始终归位到第一。
- 删除只更新集合及必要成员关系的软删除字段。旧顺序中的 ID 在读取时忽略，无需同时写入排序设置；重启和重排不会重新创建集合。
- 排序保存失败时恢复上一次已保存顺序并提示，不把临时排列当成已保存结果。

JSON 编解码集中在集合导航偏好的领域边界，沿用通用 KV 表的规则。零作品不会使有效集合消失，超出导航宽度的入口通过更多菜单访问。

## 4. 条件文档

### 4.1 外层与节点

`filter` 的外层结构固定为 `version` 和 `root`。第一版 `version` 为整数 `1`。

| 节点 | 必需属性 | 含义 |
| --- | --- | --- |
| `all` | `items`，非空子条件数组 | 全部满足 |
| `any` | `items`，非空子条件数组 | 任一满足 |
| `not` | `item`，一个子条件 | 对子条件取反 |
| `compare` | `left`、`op`，按操作符要求提供 `right` | 字段比较 |

`compare.left` 只允许 `{ "field": "稳定字段标识" }`；`right` 只允许 `{ "value": 字面值 }`。第一版不接受字段与字段比较、路径别名或用户表达式。

示例：收录创作中，并且分类为科幻或含有穿越标签的作品。

```json
{
  "version": 1,
  "root": {
    "type": "all",
    "items": [
      {
        "type": "compare",
        "left": { "field": "novel.status" },
        "op": "eq",
        "right": { "value": "in_progress" }
      },
      {
        "type": "any",
        "items": [
          {
            "type": "compare",
            "left": { "field": "novel.category" },
            "op": "eq",
            "right": { "value": "科幻" }
          },
          {
            "type": "compare",
            "left": { "field": "novel.tags" },
            "op": "contains",
            "right": { "value": "穿越" }
          }
        ]
      }
    ]
  }
}
```

根节点深度计为 1，第一版最大深度为 3，最多 50 个节点，组节点和比较节点均计数。空组、缺失子节点、额外未知属性、类型错误与超限规则均不能保存。新增条件导致超限时，编辑器给出原因并阻止该操作。

`is_empty`、`is_not_empty` 不带 `right`；其他操作必须有类型正确的右值。空文本比较值不能保存，判断空值使用专门操作符。空白字符串本身不等于空字符串，不进行隐式 trim 或大小写转换。

### 4.2 字段目录

字段标识统一使用 `novel.*` 前缀，小说和剧本均沿用底层 Novel 记录及这一字段命名空间，通过 `contentKind` 区分基础范围。

字段定义是扩展入口，包含稳定标识、值类型、合法操作符、枚举值或值校验，以及本地化标签和输入方式所需的描述。数据库字段映射由查询编译层维护，不把任意标识直接插入 SQL。

| 字段 | 值类型 | 第一版操作符 |
| --- | --- | --- |
| `novel.status` | 作品状态枚举 | `eq`、`neq` |
| `novel.type` | 作品类型枚举 | `eq`、`neq` |
| `novel.category` | 字符串 | `eq`、`neq`、`is_empty`、`is_not_empty` |
| `novel.tags` | 字符串集合 | `contains`、`is_empty`、`is_not_empty` |
| `novel.title` | 字符串 | `eq`、`contains`、`starts_with`、`ends_with` |
| `novel.word_count` | 非负整数 | `eq`、`neq`、`gt`、`gte`、`lt`、`lte` |

状态和作品类型引用现有枚举的持久化值；分类和标签从当前作品类型的基础范围提供候选，并允许保留已经没有作品使用的值。筛选现有作品时包含既有的历史作品类型值，不以新建作品表单的选项作为唯一依据。

比较语义固定如下：

- 字符串比较区分大小写，不做隐式类型转换或 Unicode 归一化。
- 标题包含为字面子串匹配，`%`、`_` 等字符不解释为通配符。
- 标签包含为完整标签匹配，`科幻` 不匹配 `硬科幻`。
- 字符串空值指空字符串，标签空值指空数组；第一版字段均非空，不接受 NULL 右值。
- 字数右值必须是非负整数，解析失败不能默认变成 0。
- 多状态选择可表达为多个 `eq` 的 `any`；包含多个标签可表达为多个 `contains` 的 `all`。
- 字数区间可表达为 `gte` 与 `lte` 的 `all`。合法但互相矛盾的条件得到零结果，不自动修正。

以后添加字段时补齐目录、输入控件、校验与查询映射；添加操作符时定义适用类型和完整语义。新增能力保持既有语义时沿用版本；改变文档结构或既有语义时升级版本并提供显式转换。

### 4.3 强类型与不支持的文档

专用 TypeConverter 将数据库文本转换为条件文档状态：有效、不支持或损坏。有效文档包含强类型节点；另外两种状态保留原始文本和可定位原因，避免一条坏规则使所有集合读取失败。

保存路径只接受完整校验后的有效文档。未知版本、字段、操作符和损坏 JSON 不自动迁移、不局部执行，也不退回全部作品。错误集合仍可在导航中看到，显示不可用原因；名称等独立修改不得重写其 `filter` 原文。

完整校验先于求值，必须遍历整棵树。例如 `any` 的第一个条件已经满足，也不能跳过后面未知字段的校验。

`filter` 是有版本、固定节点类型和完整校验的专用业务列，不使用 schemaless metadata。第一版不存放外部实体关系；未来涉及集合引用等关系时需显式建模。

## 5. 查询与响应式更新

所有集合先应用不可编辑的基础范围：作品类型与当前书库一致、`deleted_at` 为项目未删除哨兵值、`draft` 为 false。基础范围位于用户条件树之外，取反和任一满足都不能绕过它。

```text
集合定义 + 基础范围
        |
        v
完整校验 + 字段目录
        |
        v
查询编译器
        |
        +--> 当前集合作品列表
        +--> 条件预览
        +--> SQL COUNT 计数

编辑器 --> 保存校验 --> 集合 DAO --> 数据库变更通知 --> 重新查询
```

先校验集合配置：受保护的全部集合仅使用基础范围，手动集合以有效成员关系限制作品范围，普通规则集合将已保存条件树编译为参数化谓词。初始化创建的两个状态集合与其他普通规则集合使用同一查询路径。所有查询使用显式字段映射和操作符白名单；集合 ID、枚举和用户文本均参数绑定。

列表、预览和计数共享谓词构建，只有投影和分页不同。计数使用 SQL 聚合，不为导航计数载入所有作品。标签匹配在查询层按 JSON 数组元素做精确比较，不对序列化后的整段文本做模糊匹配；实现时需在项目锁定的 SQLite 运行环境验证中文、转义字符和空数组行为。

拆开现有 `LibraryCollection` 同时携带定义和完整作品列表的职责：导航只消费集合定义、计数与状态；当前集合单独订阅作品。成员选择器只查询手动集合及待选作品的成员关系，不再依赖所有集合的完整作品快照。

导航计数采用按作品类型组织的批量查询，一次输出该类型的可用集合计数，避免每个集合建立独立作品流。涉及自定义查询时，显式声明作品表、集合表、成员关系表的更新依赖。单条规则编译失败时隔离该集合，不连带其他集合计数失败。

规则修改、作品状态或标签变化、成员加入移出、作品软删除及草稿加入书架都触发对应结果更新。编辑规则时保留最后一次保存的正式结果，草稿预览单独查询；旧预览响应不能覆盖较新的编辑状态。文本输入遵循现有 debounce 规则。

## 6. 导航与编辑行为

首页移除独立的集合封面区，在当前状态标签位置展示统一集合导航。切换集合只替换作品区，页面上方的问候、最近创作等区块保持不变，不再进入带返回的集合详情页。草稿箱继续独立。

桌面作品区顶部只有一行：左侧是集合标签，末尾为新建集合入口，宽度不足时收进“更多”菜单，当前选中项始终可见；右侧依次为搜索、分类过滤、作品排序和草稿箱（仅在全部集合下出现）。搜索从侧栏移入这一行，只作用于当前作品类型和当前集合；侧栏不再放作品搜索。

移动端依次为标题栏、小说 / 剧本切换、搜索框、集合行，其下为作品网格。集合行左侧横向滚动展示集合标签，末尾为新建集合入口，右端固定过滤按钮，打开包含分类和作品排序的面板，生效时按钮高亮。滚动时仅集合行吸顶。

集合操作通过桌面右键、移动端长按集合标签触发，菜单包含重命名、左移、右移和删除集合；全部集合不响应。不设单独的管理集合弹窗，也不在集合菜单中提供添加作品。

桌面可直接拖动集合标签排序，并通过集合菜单的左移、右移完成同样操作；移动端只提供左移、右移。全部集合固定第一，不可移动。小说、剧本分别保存顺序。移动端现有集合路由保持可达，落到书架并选中对应集合；用户集合 UUID 不变；所有集合统一按实际数据库 ID 导航和查询，无虚拟标识分支。

新建流程：选择手动或条件收录，填写名称；手动模式使用现有选作品流程，规则模式编辑条件并预览结果。保存失败保留输入，成功后进入新集合。名称、模式和条件在同一创建事务写入，防止半成品集合。

条件编辑器按树原样呈现，支持全部满足、任一满足、取反与字段比较，深度上限内允许组合；状态和类型使用选择控件，分类与标签使用候选输入，字数使用整数输入。不向用户暴露 SQL 或 JSON。

现有 `ConditionBuilder` 只编辑固定的 `any -> all -> compare` 结构，并会把未知字段替换为默认字段。第一版不直接复用该组件解析集合条件，也不为集合顺手重构通用条件组件。集合编辑器复用项目基础表单和选择组件，严格保留树结构；不支持的节点只读显示原因，不能通过打开编辑器自动覆盖。

保留分类过滤和作品排序控件，桌面工具栏及移动端过滤 / 排序入口继续可用。移除临时状态筛选：状态范围由创作中、已完本等集合承担，首页原状态标签的位置改为集合导航。删除“创作中”等默认集合后，不再提供按状态浏览的临时入口，需要时由用户重新建立规则集合。

作品区域统一采用响应式网格，移除桌面的表格 / 列表渲染分支、网格与列表切换按钮及对应视图模式状态；移动端延续现有网格布局，并检查窄屏适配。列数按可用宽度调整，窄屏允许单列卡片网格，但不提供独立的行式列表模式。保留卡片上的打开、状态修改和菜单操作，不因删除旧列表分支丢失能力。

工具栏筛选和搜索只作用于当前集合，清除后恢复该集合范围。切换集合时清空临时筛选，保留页面搜索输入；当前搜索继续在新集合内执行。搜索框与过滤控件自身显示生效状态，不单独增加筛选标记行。作品排序保留为页面状态，切换集合时沿用当前选择，不写入集合记录或 `filter`。

集合计数表示基础范围内该集合的完整成员数，不随临时搜索变化；过滤后不单独显示结果数量，零结果时显示空状态。规则入口只通过明确的编辑和保存修改，临时过滤不自动写回。第一版无需增加“把当前筛选保存为集合”的快捷入口。

没有匹配作品时保留选中集合与条件，显示空结果；不能沿用现有“状态消失就回到全部”的行为。删除当前普通集合成功后回到全部，删除失败保持当前位置；删除其他集合不改变当前选择。

移除作品多选模式及批量浮条。作品加入、移出集合通过卡片菜单的“加入集合”完成；手动集合为空时，空状态提供从书架挑选作品的入口。

## 7. 数据迁移与回退

给集合表增加 `builtin`、`filter_mode` 与 `filter`，旧行自动成为 false、`manual`、NULL。集合 ID、创建时间、软删除状态和成员关系全部保留，不重写作品。排序偏好缺失时按默认规则计算，无需批量写入。结构升级后由 `default_collections_v1` 初始化默认记录，schema migration 不混入种子写入或完成标记。

不在本文凭分支版本号判定是否已发布。实施时执行以下确定流程：

1. 核对实际发布记录、发布标签及标签对应的 schema，记录依据。
2. 如当前 schema 已发布，提升到实施时当前版本加 1，增加正式 migration，并同步生成模型。
3. 只有确认当前 schema 尚未发布，才把新增列合并到该 schema 的集合建表 migration，保持版本不变；开发数据库按 SQLite skill 的流程手动补列并查询验证。
4. 检查所有涉及集合表的历史建表和重建逻辑，保证跨版本升级保留原值且能通过 Typed DAO 读取。
5. 从仍受支持的正式版本真实结构 fixture 验证直升；至少包含集合引入前与已有手动集合的数据库。

项目 `db-migration.md` 的常规要求是提升版本；只有根 `AGENTS.md` 明确规定、且经发布证据确认的未发布分支可以使用合并 migration 的例外。不得为本地 schema 漂移增加运行时 fallback。

迁移失败按现有数据库启动错误路径报告，不删除数据库重建。迁移回退使用实施前备份，恢复会舍弃备份后的写入，不能自动执行。上线后的优先修复方式是向前修复或隐藏新的编辑入口并保留字段和数据；不保证旧客户端能理解规则集合，不把直接安装旧版本作为安全回退方案。

## 8. 实施文件与顺序

本方案预计涉及超过 8 个文件，覆盖共享数据层、两端书库和测试；不新增后端接口、第三方依赖、账户、密钥或 AI 调用。第一版复用现有初始化服务结构，单库业务写入由 DAO 事务承担，默认数据通过初始化任务的事务写入。

### 数据与领域模型

- `lib/shared/models/novel_collection.dart`：分离集合定义与作品快照，表达 `builtin` 保护标记、集合模式和规则可用状态，所有集合均有数据库记录。
- 新增 `lib/shared/models/collections/filter.dart`：文档版本、强类型节点、完整校验与保留原文的解析结果。
- 新增 `lib/shared/models/collections/fields.dart`：第一版字段目录、值类型、操作符与值校验，不依赖 Widget。
- `lib/shared/database/type_converters.dart`：新增专用条件文档转换器，业务层不手动编解码专用列。
- `lib/shared/database/app_database.dart`、`app_database_migrations.dart`：列定义与经发布核验确定的迁移。
- 新增 `lib/shared/database/queries/collection_filter.dart`：字段映射、参数化条件编译和基础范围；不接受自由 SQL。
- `lib/shared/database/daos/novel_collection_dao.dart`：定义读取、模式校验、事务创建和编辑、当前集合查询、批量计数与手动成员查询；删除和编辑边界校验 builtin，种子去重查询包含软删除记录。
- 新增 `lib/shared/services/initialization/collection_seeds.dart`：固定种子、事务插入与包含软删除的幂等检查；两种作品类型一次初始化。
- `lib/shared/services/app_initialization.dart`：注册 `default_collections_v1`，沿用现有任务执行与完成标记机制。

### 状态与界面

- `lib/shared/providers/novel_collection_providers.dart`：分别暴露定义、计数和当前集合结果，并维护集合导航顺序偏好；避免循环依赖和逐集合完整列表订阅。
- `lib/shared/widgets/collections/location.dart`：按数据库 ID 管理当前集合、缺失状态及两端导航，回到全部时查找当前类型的 builtin 记录；缺少有效全部记录时展示初始化失败状态。
- `lib/shared/widgets/collections/shelf.dart`、`header.dart`、`empty.dart`：将集合封面区替换为统一导航与集合右键 / 长按菜单，按 builtin 标记决定菜单能力并更新空状态；删除集合详情页头与 `manage.dart` 管理弹窗。
- 新增 `lib/shared/widgets/collections/filter_editor.dart`：受控树编辑、类型化输入、错误定位和草稿预览；本地编辑态使用项目表单与 Hooks 约定。
- `lib/shared/widgets/collections/name_dialog.dart`、`membership_picker.dart`、`work_picker.dart`、`work_menu.dart`：新建模式选择与规则编辑接入，只向手动集合提供成员写入入口；删除 `selection.dart` 及多选入口。
- `lib/desktop/widgets/home/library_home_panel.dart`、`all_works_header.dart`：统一集合范围，移除状态临时筛选，保留分类过滤和作品排序，集合导航与工具合并为一行并接入搜索，移除重复状态导航、视图模式切换及无匹配时的自动回退；侧栏移除作品搜索框。
- `lib/desktop/widgets/novel_list.dart`：只保留网格渲染，删除旧表格 / 列表分支及 `isGridView` 参数，保留网格中的所有作品操作。
- `lib/mobile/pages/library_page.dart`：接入同一集合和条件模型，处理导航、长按集合菜单（改名、左右移动、删除）与移动端编辑；作品区域延续网格布局并检查窄屏适配。
- `lib/mobile/features/library/filters.dart`、`shelf_options_sheet.dart`：保留并衔接临时过滤和作品排序能力。
- `lib/shared/localization/locale_keys.dart`、`assets/translations/en/library.json`、`assets/translations/zh-CN/library.json`：补齐模式、字段、操作符、左移右移、删除、错误和空状态文案；视图切换文案只在确认无其他调用后清理。

生成源修改后更新对应生成文件并检查 diff。首页集合导航与网格的设计稿在现有原型中：桌面 `designs/desktop/LibraryView.jsx`、`LibraryCollections.jsx`、`library_collections.css`，移动端 `designs/mobile/m_home.jsx`（`LibraryScreen`）、`m_collections.jsx`。

### 实施依赖顺序

设计正文保留完整的条件模型与规则编辑方案。本节限定当前版本的执行范围：UI 只开放手动集合的创建和编辑，不开放 filter 模式选择、规则集合创建、条件编辑或条件预览。正文中涉及这些 UI 的文件、文案和验收项属于后续任务，本次不创建对应组件或测试，也不把未执行的验收项报告为通过。

默认的全部、创作中、已完本仍按设计初始化并可在 UI 浏览；其规则查询能力属于当前版本的数据层任务。创作中和已完本可以改名、排序、删除，但不提供条件编辑或手动成员增删。用户新建集合固定为 `builtin=false`、`filter_mode=manual`、`filter=NULL`，不展示模式选择器。手动集合沿用现有名称编辑、作品加入和移出流程。

```text
T1 数据结构、校验与查询
  -> T2 migration、默认集合初始化与 DAO 保护
  -> T3 集合订阅与导航顺序
  -> T4 两端 UI：手动管理、默认集合浏览、仅网格
  -> T5 当前版本验收与交付

T5 交付后
  -> T6 后续版本：规则集合创建、条件编辑与预览 UI
```

| 任务 | 范围 | 完成依据 |
| --- | --- | --- |
| T1 | 集合列、条件文档、转换器、校验和查询编译；手动成员、默认状态规则、受保护全部的查询与计数 | 数据模型及查询测试通过；不依赖条件编辑 UI |
| T2 | schema migration、`default_collections_v1`、builtin 保护、包含软删除记录的种子去重 | 旧库升级、首次启动、失败重试和软删除不恢复测试通过 |
| T3 | 定义、计数、当前集合作品订阅与导航顺序，替换完整作品快照依赖 | 默认集合与手动集合按相同导航模型展示，计数及作品更新一致，顺序可持久化 |
| T4 | 桌面和移动端的统一导航、手动集合新建与管理、普通默认集合改名和删除；保留工具栏临时过滤与作品排序，移除列表模式 | 两端仅有网格；没有模式选择、规则创建、条件编辑或预览入口；用户新建始终保存为 manual |
| T5 | 第 9 节中属于 T1 至 T4 的测试及人工验收，检查生成 diff | 当前版本可以独立使用和交付，不依赖 T6 |
| T6 | 后续按完整设计接入 filter 模式选择、规则集合创建、条件编辑、预览及相应文案和测试 | 不属于本次执行范围，后续明确启动后再实施 |

当前保留的 UI 临时过滤和作品排序只作用于正在浏览的集合，不编辑或保存集合的 `filter`。T4 不新增 `filter_editor.dart`，T5 不新增或运行其专属测试；人工验收改为新建手动集合、管理成员、浏览默认集合、验证状态自动更新、改名与删除、集合排序、网格布局及现有临时过滤和作品排序。第 9 节中的规则创建、条件编辑和预览验收随 T6 执行。

T1 至 T5 是当前改动内部的依赖顺序，完成后整体交付；T6 可独立安排，不以半成品按钮、隐藏入口或占位组件提前接入。

## 10. 风险与扩展边界

复杂条件的主要成本来自作品数量与集合数量的乘积。第一版限制树复杂度、批量计数并避免加载正文；实施时用查询计划检查标量条件是否可利用既有索引，按实际查询补必要索引。标签查询允许扫描候选作品的标签数组，不承诺所有组合都能使用索引。性能验证使用 100 个集合、1 万部轻量作品，确认查询批次不随集合数量变成逐集合往返，记录实测耗时，不虚报性能指标。

集合条件与通用条件求值器复用语法，不共享宽松类型转换行为。集合预览与列表都通过 SQL 查询，不能再写一套 Dart 内存过滤作为生产 fallback。对合法输入可用现有求值器做测试对照；不得据此接受它支持的额外路径或类型强制转换。

将来加入日期、相对时间或其他集合引用时，需要分别定义时区和时钟更新、引用生命周期和循环校验。它们不作为第一版占位节点写入规则，也不在界面提供尚不能执行的选项。
