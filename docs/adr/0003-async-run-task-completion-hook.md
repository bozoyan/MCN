# Async task launch with comment-stream callbacks

The Remote Assistant launches Task Runs via Run task subcommands. Task Runs may take minutes to complete, and the Remote Assistant should keep the user informed and able to intervene mid-run, not just receive a final result. We decided task launch is asynchronous — the Assistant starts the task and returns immediately with a "started" acknowledgement. Callbacks flow through the **Task Comment** stream (see ADR-0005): every Task Comment authored by the Task Run's Orchestrator (via the task-context-injected `task_comment` tool) re-wakes the Remote Assistant Session as a new turn seeded with the comment content. The Assistant then decides per-turn whether to forward the comment to the Remote Channel, reply to the user, write its own Task Comment, or call other tools. We chose this over synchronous blocking (the Assistant session would be held busy for minutes with no concurrency), over a single settle-time hook (the user would be blind during the run and unable to redirect), and over direct task-to-channel push (the Assistant's ability to summarize, contextualize, or translate user replies into Task Comments would be lost).

## Consequences

- The Assistant's turn ends after "已启动"; the user can send more messages while the task runs.
- The Assistant must support receiving task-comment-callback turns out-of-band — its prompt and tool set must handle a turn seeded with a Task Comment rather than a user message.
- Task Run completion is coupled to the Remote Assistant Session lifecycle via the comment stream. The Task Comments themselves persist (in the Task Comment table), but the *trigger* to re-wake the Assistant does not survive app restart — V1 accepts this loss (no fallback scan). Comment content remains queryable via Run comment list subcommands after restart.
- The Assistant, not the task, owns the decision to forward to WeChat. A chatty Orchestrator could flood the channel; the Assistant prompt must be instructed to summarize or batch rather than forward every comment verbatim.
- User messages from WeChat are not auto-injected as Task Comments. The Assistant interprets each user message and decides whether to write a Task Comment (mid-run redirect), reply directly, or take another action.
- Resolved: the callback is a normal AI chat message (no special message type). The Task Comment content is injected as a synthetic user message; the Assistant recognizes comment-sourced turns from content (the prompt instructs it how to interpret them).
- Resolved: the Assistant sees individual Task Comments as turn seeds, not the full Task Run Session transcript and not a `ChatTurnOutcome` object, to control token cost. It can call Run comment list subcommands to fetch prior comments when more context is needed.
